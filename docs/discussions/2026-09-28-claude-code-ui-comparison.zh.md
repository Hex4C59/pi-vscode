## 背景

维护者对照 Claude Code 空窗界面与本扩展侧栏，询问为何前者更有质感／更好看，以及 Pi 应如何设计。

这不是对现有 CSS 的缺陷报告。当前外观遵循已确认的产品简报。

## 依据

**Claude Code（截图，2026-09-28）：** 全窗产品、大块留白、品牌珊瑚色标志、编辑性欢迎文案、内边距充足的公告卡片、作曲区是被塑造的对象（暖色焦点环、实心品牌发送按钮）。

**Pi 当前实现：**

- 产品简报（[PRD WI-015／视觉重设计](../product-requirements.zh.md)）：紧凑、**IDE 原生**、VS Code 主题色／字体、**320–400px** 侧栏（可到 280px），以 Codex 为简洁参照。不追求与独立聊天应用像素一致。
- `src/webview/styles/theme.css` 的 token：`--ui-bg`／`--ui-fg`／`--ui-focus`／`--ui-accent` 全部映射 VS Code。`--ui-radius: 6px`。没有独立于宿主主题的产品强调色。
- `src/webview/chat/candidate.tsx` 空状态：38px 的 `assets/pi.svg` 蒙版，填 `--ui-fg`；标题 “What should we work on?” 19px；副标题 12px 弱化。无卡片、无品牌色。
- `candidate.css` 作曲区：13px 圆角、1px `--ui-border-strong`、焦点为 `--ui-focus`（VS Code 蓝）。发送是 30×30 的 `--ui-fg` 底 `--ui-bg` 字。正文 13px，铬件 11px。

WI-024 仍在等供应商设置的 F5 验收。本次对比不授权视觉重写或新 WI。

## 观感差异从何而来

差距主要是**画框**，其次才是**工艺**。

| 杠杆 | Claude Code | Pi 侧栏 |
|------|-------------|---------|
| 舞台 | 全窗；留白本身就是产品 | 280–400px 辅助侧栏，旁边是资源管理器 |
| 颜色 | 设计过的暗底上只有一种珊瑚色 | 宿主主题 token；没有 Pi 强调色 |
| 空状态 | 品牌时刻（标志、问候、卡片） | 小灰标 + 两行工具文案 |
| 作曲区 | 大型对象：厚圆角、暖色环、实心发送 | 细 1px 框；焦点是 IDE 蓝 |
| 密度 | 铬件很少、点击目标大 | 同一条带里挤着历史／新建／齿轮、模型、thinking、+／审批／审阅 |
| 字体 | 问候偏编辑、正文安静 | 通篇 11–13px；标题几乎不更大 |

把 Claude Code 的画布搬进这条侧栏，会和已接受的 IDE 原生简报冲突，也会撑爆宽度预算。可迁移的是工艺，不是布局。

## 当前倾向（代理；不是决定）

保持**侧栏／VS Code token** 产品。若日后批准视觉切片，提高工艺，但不变成独立聊天应用：

1. **一种克制的 Pi 强调色**，用于空状态标志、作曲区焦点和发送——在浅／深／高对比下仍可读；不替换主题底色。
2. **把空状态做成时刻：** 更大标志、更多纵向留白、一句问候 + 一行弱化说明。没有真实消息时不要做公告卡片。
3. **只把作曲区塑造成对象：** 略大圆角、更软边框、Pi 强调色焦点环、发送改为实心强调控件，而不是反色前景。
4. **空闲时空状态少同时显示铬件行**；审批／错误／Stop 出现时仍要醒目。
5. **字号阶梯：** 空闲铬件 12px、正文 13px、空状态标题明显更大；不要把 10–11px 当默认语气。

除非明确修订 PRD 简报，否则不做：全窗聊天、独立于 VS Code 的自定义暗色、Plan 模式、装饰插画，或把 F5 观感当成 WI-024 验收。

## 请维护者决定的问题

1. 继续 Codex／IDE 原生简报，还是允许在 VS Code token 之上做**有界品牌叠加**（强调色 + 空状态 + 作曲区）？
2. 若允许，是否等 WI-024 F5 之后，再单独 Prepare 一个视觉工艺 WI？
3. 浅色／高对比：强调色必须是带回退的 token，不能写死珊瑚色。
