## 问题

维护者觉得作曲区 **执行配置** 不好理解，更希望设置里有专门管插件的地方：下载、卸载、启用和关闭已经下载的插件。

代理判断：那是插件管理器，不是把现在两行执行配置挪个位置。当前受信路径只为**这一次** runtime 挑选一个本地入口。新 runtime 仍从受控开始。PRD 不隐含市场、安装 UI 或包管理交付。额外扩展生态仍为 standing non-goal，下文停放的本机清单切片除外。

## 2026-10-01 已记录决定

维护者要求把大想法拆成小任务，写入 ACTIVE 停车场，供之后串行实现。记录不是 Prepare 完成、Build 批准、PRD 变更或 ADR。每个切片仍须单独提案并取得维护者 Build 确认。在某一切片晋升前 WIP 保持 0。

下载／市场在另一次明确确认前仍排除。停放切片里的卸载指**从清单移除**，不删除磁盘文件，除非后续切片另有规定。

## 当前产品（不要当成管理器）

- 受控执行：仅内置工具；覆盖的调用仍要审批。
- 受信执行：原生文件选择器＋宿主确认后，为本次 runtime 加载该入口。
- 仅空闲时切换配置；失败须显式恢复。
- WI-013 接受一个本地选定目标（pi 0.86.1 上的 `pi-system-prompt-manager` 0.1.1），不是任意生态兼容。

## 切片 1 结论（WI-059）

已记入 [REQ-010](../product-requirements.zh.md) 与 [Draft ADR 0010](../decisions/0010-local-plugin-inventory.zh.md)：

- 启用表示有资格进入**下一次空闲受信应用**。受控从不加载清单项。
- 清单属于本 **VS Code 配置**（`globalStorageUri`），不是按窗口或工作区。
- 启用不是加载同意。原生确认仍覆盖将要加载的路径。
- 从磁盘添加只**记住绝对路径**，不拷贝文件。

## 倾向

先做设置里的**本机清单**，再谈任何下载 UI。工具审批继续询问。持久化与信任按 ADR 处理；该 ADR 在后续切片验证存储与同意之前保持 Draft。
