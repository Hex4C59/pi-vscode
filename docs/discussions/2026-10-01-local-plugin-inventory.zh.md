## 问题

维护者觉得作曲区 **执行配置** 不好理解，更希望设置里有专门管插件的地方：下载、卸载、启用和关闭已经下载的插件。

代理判断：那是插件管理器，不是把现在两行执行配置挪个位置。当前受信路径只为**这一次** runtime 挑选一个本地入口。新 runtime 仍从受控开始。PRD 不隐含市场、安装 UI 或包管理交付。额外扩展生态仍为 standing non-goal，下文停放的本机清单切片除外。

## 2026-10-01 已记录决定

维护者要求把大想法拆成小任务，写入 ACTIVE 停车场，供之后串行实现。记录不是 Prepare 完成、Build 批准、PRD 变更或 ADR。每个切片仍须单独提案并取得维护者 Build 确认。在某一切片晋升前 WIP 保持 0。

下载／市场在另一次明确确认前仍排除。停放切片里的卸载指**从清单移除**，不删除磁盘文件，除非后续切片另有规定。

## 当前产品（不要当成管理器）

- 受控执行：仅内置工具；覆盖的调用仍要审批。
- 受信执行：原生文件选择器＋宿主确认后，为本次 runtime 加载该入口。
- 仅空闲时切换配置；失败须显式恢复。
- WI-013 接受一个本地选定目标（pi 0.86.1 上的 `pi-system-prompt-manager` 0.1.1），不是任意生态兼容。

## 停放切片顺序

一次只晋升 **一行**。除第 7 项可在设置列表已能管理时推迟外，前序必做项未完成时不要开始后项。

| 顺序 | 切片 | 范围内 | 范围外 | 依赖 |
|------:|------|--------|--------|------|
| 1 | 产品边界（Prepare，仅文档） | 清单≠当场加载；列表存哪里；启用／关闭对下次空闲 runtime 的含义；与受控／受信的关系；PRD 切片；ADR 类（持久化或信任变化则为 `adr-after-approval`） | 无代码、无 UI、无市场 | — |
| 2 | 宿主清单存储 | 本地路径身份＋ enabled 标志；缺失／损坏／过大文件保持不变；密钥不进 Webview 或 `postMessage` | 不加载 runtime、无设置 UI | 1 |
| 3 | 设置「插件」分类：空列表＋从磁盘添加 | 原生选择器写入清单；空、重复、无效路径 | 不改变启动加载 | 2 |
| 4 | 从清单移除 | 删除清单项；说明磁盘文件仍在 | 不卸载 pi 全局包、不删除扩展目录 | 3 |
| 5 | 启用／关闭 | 持久化标志；说明正在跑的 runtime 须空闲重建／切换后才变 | 不静默改活的受信加载 | 3 |
| 6 | 已启用项接到 runtime | 空闲启动或配置切换时经公开 pi API 加载已启用项；覆盖警告；失败恢复不变 | 不跳过工具审批；不自动发现未列入路径 | 1 与 5 |
| 7 | 作曲区入口收拢 | 权限／作曲区显示状态（恢复必要时仍可见）；添加／移除／启用在设置里 | 不改加载语义 | 6 |

**以后才考虑（不进本串行队列）：** 下载、市场、远程目录、自动更新、签名包、未经确认就对所有窗口默认启用。

## 切片 1 仍待决

- 启用是「下次受控启动就加载」，还是「仅受信配置时加载」？
- 清单按 VS Code 窗口、工作区，还是用户 profile？
- 清单里已有路径，第一次启用是否仍要现有宿主确认？
- 从磁盘添加是复制到产品目录，还是只记住所选路径？

## 倾向

先做设置里的**本机清单**，再谈任何下载 UI。工具审批继续询问。持久化与信任在切片 1 按 ADR 处理，不要拖到切片 6 才发现。
