## 背景

ADR 0002 在扩展的全局存储里保留恢复 fence。重新加载、看不到进程，以及空窗口，都不能清掉它。侧栏会显示「运行时结果不确定」，并等待先结束自有运行时，再恢复受控执行。

2026-09-29 维护者要求打开侧栏时与 Claude Code、Codex 相同：没有恢复黄条，也没有结束／恢复两步。随后选定遗留进程的规则：先结束它，再开始对话。

## 决定

1. **侧栏没有恢复步骤。** 打开、重新加载，或使用没打开文件夹的窗口，不显示恢复黄条，也不等待恢复受控执行。
2. **先结束遗留运行。** 宿主启动时如果还记录着上一个自有子进程，宿主先结束它，等到观察到退出，退休那份 fence，然后显示正常的空对话或无文件夹页。用户不确认这些步骤。
3. **同时只有一个自有子进程。** 上一次自有子进程仍是当前记录时，不启动替代进程。

## 理由

黄条会挡住一个并没有开始这次对话的窗口。在页面就绪前结束遗留子进程，可以去掉这一步，并让下一次对话只对应一个自有 `pi`。

## 考虑过的替代方案

- 保留黄条和两个恢复操作：已拒绝。维护者不需要这套流程。
- 只隐藏黄条、fence 仍留着：已拒绝。下一次启动仍会被挡住。
- 忽略 fence、让旧子进程继续运行：已拒绝。维护者选择先结束它，再开始对话。

## 影响

宿主启动时可能未经对话框就停止遗留的自有子进程。它尚未完成的工作会丢失。该子进程退出仍不能证明它的后代已停止，也不能证明文件改动已回滚。若结束后没有观察到退出，这时的页面不在本决定内。在本 ADR 标为 Accepted 之前，ADR 0002 保持 Accepted。写下本记录时没有改应用代码。
