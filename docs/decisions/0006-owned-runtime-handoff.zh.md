## 背景

[ADR 0002](0002-interaction-contract-route.zh.md) 在宿主丢失后保留 fence 和独立的精确子进程观察者。此前下一个宿主即使没有文件夹，也显示不确定黄条并要求先结束、再恢复。维护者选择先结束上一宿主遗留的运行，再正常打开。WI-035 补齐失败和活宿主分支；实现批准不接受整份 Draft PRD。

## 决定

1. **扩展激活时交接。** Provider 构造开始一次交接。目前由 `onView:pi-vscode.chat` 激活，不等于 VS Code 应用启动时就执行。新运行时等待交接，并重新核对 disposal、工作区身份、资格与资源选择。交接不授予工作区信任或资源同意，不重放任务。
2. **先观察再结束。** 已有匹配终态回执时直接退休，不请求结束。否则经既有有界、经校验的控制通道查询精确 supervisor。仅 `owner-lost` 允许自动结束；`owned` 表示另一活宿主，不结束或退休其运行，本窗口也不显示 End／Recover。此处尝试启动只报告共享域被占用，不创建替代进程。
3. **先回执再退休。** 结束确认和信号发送不是退出证据。退休前须有同时匹配 run 与 child 的持久回执。控制状态 `exited`／`never-spawned` 也不能代替回执。结束观察最多 10,500 ms；终态回执落盘等待最多 1,000 ms；控制往返保持 1,500 ms／4 KiB 边界。
4. **确认清理后正常页面。** 空域或成功退休显示正常空对话／无文件夹页，无恢复黄条和两步仪式。启动新运行时仍需受支持且有资格的本地工作区与新的资源选择。
5. **失败诚实。** 监督不可达、退出不确定、记录无效或退休失败时保留 barrier 和既有显式恢复页。不终止任意 PID，不按年龄过期，也不提供清除未知旁路。另一窗口已退休时，重新观察空域可清除失效恢复页。独占退休只允许一个写入者，不保证所有并发调用立刻成功。
6. **保留既有边界。** global storage 共享域只允许一个运行时；`recovery-v1` schema 与 Webview v3 DTO 不变。同宿主 Stop／协议故障仍需显式 End／Recover。managed-process 交接与 cleanup 串行，拒绝活跃／在途启动，不清除更新代际的 blocked 状态。

## 理由

后来的宿主不应要求人工清理可证实的遗留运行。先观察可以区分遗弃运行和另一窗口的活跃工作；精确回执保留已接受的准入安全。渲染器仍无权清除 fence。

## 考虑过的替代方案

- 保留启动黄条和两个操作：维护者拒绝。
- 藏起黄条但保留未决 fence，或忽略 fence 并发启动：拒绝，均不符合安全交接目标。
- 自动结束另一窗口的活宿主：拒绝，共享存储不意味着其运行是遗留运行。
- 每窗口独立恢复域、或 owner loss 当场清理：是另一个未来决策，作为 WI-036 候选保留在 ACTIVE，本项不实现。

## 影响

下一次激活可能无对话框地中断前任宿主的直接子进程。其退出不证明后代停止、命令成功或文件回滚。宿主完整崩溃仍丢失纯内存草稿。崩溃退休写入者留下的 marker 仍是保守 barrier；本项不绕过 marker 或迁移记录。实际 F5／安装、活所有者安全与清理证据，初始配置／工具失败及保留限制见 [WI-035 代理受托接受](../archive/2026-09-30-wi-035-macos-acceptance.zh.md)。
