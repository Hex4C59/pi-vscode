## Context

当前受信执行通过原生选择器加宿主确认，为**这一次** runtime 挑选**一个**本地入口。新 runtime 从受控开始。维护者希望设置里能列出、添加、移除并启用已经在磁盘上的 pi 扩展。那是清单，不是把两行执行配置挪位置。下载、市场、远程目录和自动更新仍排除。

列入路径不等于加载。持久化与信任必须在存储或设置 UI 出现之前定下来，否则切片 6 会临时发明它们。

## Decision

1. **清单不是当场加载。** 清单是宿主拥有的本地 pi 扩展入口路径加上启用标志。添加、移除或开关不会启动、停止或改写活 runtime。
2. **存在本 VS Code 配置下，不是按窗口或工作区。** 在扩展 `globalStorageUri` 下存有界 JSON，与 `recovery-v1` 分开。缺文件等于空列表。损坏或过大的文件保持不改写（切片 2）。文件里没有密钥、扩展源码、提示或对话。Webview 与 `postMessage` 只收无密钥投影。
3. **启用表示有资格进入下一次空闲受信应用。** 受控执行仍只加载自带工具，从不应用清单项。正在跑的受信 runtime 要等到空闲重建或切换配置时，才按当时的启用集合应用。
4. **加载同意仍是单独的原生确认。** 现有 `selectTrustedExtension` 身份检查（绝对路径、允许后缀、大小、realpath、普通文件、非符号链接、非敏感路径、TOCTOU）仍是加载同意路径。选择器用于**加入清单**。切到受信或应用已启用项时，仍须对将要加载的路径做现有覆盖警告确认。启用不是该确认。项目资源同意仍不是扩展加载同意。
5. **只记住所选路径，不拷贝文件。** 本产品的卸载是从清单删除条目。磁盘文件仍在，除非以后有切片明确另说。
6. **只经公开 API 应用。** 切片 6 在空闲受信启动或切换时，用已文档化的 pi CLI／RPC 加载已启用项。若当前 pinned 发行版只接受一个 `-e` 入口，最多应用一条已启用路径；多出来的已启用项须可见失败。不自动发现未列入的路径。覆盖范围内的工具调用仍询问。

## Rationale

配置范围的文件对应「我的插件」，不把清单绑到恢复域或某个文件夹。受控忽略清单，保留 REQ-006 的默认。清单变更与加载同意分开，避免设置页变成静默受信启动。只存路径对应「从清单移除、磁盘仍在」。公开 API 应用避免第二条加载通道。

## Alternatives considered

- 受控启动也加载已启用项：拒绝；那会把两个策略维度并成一个。
- 按窗口或工作区列表：拒绝；窗口已有独立 runtime（ADR 0009）；插件清单是用户配置偏好。
- 拷贝进产品自有目录：拒绝；卸载就会变成删文件，停放切片禁止。
- 另存「已经同意」位并跳过原生确认：本 ADR 拒绝；加载同意仍是现有对话框。后续切片仍可用一张对话框确认一组路径，而不再打开选择器。
- 用 `globalState` 当主存储：拒绝；有界文件的 schema、大小上限和损坏不改写规则更清楚。

## Consequences

后续切片交付前，消息编辑区执行配置仍为这一次 runtime 选一个入口。交付后，设置负责添加／移除／启用；作曲区显示状态和恢复。ADR 保持 Draft，直到存储落地、损坏／大小规则有测试、加载仍不能跳过确认。不关闭 gate。
