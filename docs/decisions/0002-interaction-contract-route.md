## Context and scope

REQ-006/009 require explicit trusted extension loading and standard interaction presentation on unmodified released pi, retaining tool approval and honest Stop/recovery boundaries. Public RPC does not provide generic remote consumption, closure or origin authentication; local generations, single reply attempts and owned-child exit must not be exaggerated into those facts. Retain [ADR 0001](0001-build-baseline.md)'s subprocess RPC rather than replacing the agent loop, providers or compaction.

The [superseded candidates](../archive/2026-09-28-wi-013-superseded-candidates.md) preserve the September 22 route-1-plus-route-3 and Prepare context. Upstream enhancement is not a delivery prerequisite. The selected decisions and public evidence below own the current meaning; exact DTOs have one source in the [message contract](../reference/webview-messages.md).
## Accepted current-release decisions

Under the September 27 UTC delegation, the agent selects and implements the bounded decisions below. Recovery, DTOs and tool coverage are defined in the current contract; final acceptance and evidence limits are recorded separately, never inferred from design approval.

1. Keep pi 0.86.1 public CLI/RPC, not a fork or replacement agent loop. Explicitly selected local extension entry files are loaded only after idle-time consent; automatic discovery remains disabled. The reviewed representative is pi-system-prompt-manager 0.1.1 at commit 9c8f546b875f929ad5d573fe30e7a7fd6e3ae924, MIT. Its four normal standard forms justify select, confirm, input and editor together. No automatic download, marketplace or arbitrary TUI renderer is added.
2. Use one active form and at most seven queued forms. Each interaction JSON frame is at most 65,536 UTF-8 bytes; text/answer at most 32,768 bytes; title at most 512 bytes; select at most 64 options with 1,024 bytes per option and the aggregate frame bound. No truncation of actionable labels/answers. These budgets leave substantial headroom above the reviewed target's observed 148–315-byte frames and five-option menu while bounding retained interaction payload to at most eight frames. The existing general RPC reader has a separate bound; this decision does not falsely make its partial-frame buffer 64 KiB or shrink attachment/model payload contracts. Decoding, framing and separate budgets remain protected by regression evidence.
3. Cancel overflow requests through the supported response when possible; do not evict already-admitted forms. Five overflows in a rolling ten-second window invalidate interaction admission and hold a visible failure barrier, without auto-killing/restarting or claiming remote work stopped. Ordinary human response has no arbitrary timer. Admitted startup dialogs pause the remaining 15-second readiness-response budget, not Stop observation. Reply transport admits at most 16 in-flight writes with shared listeners and a five-second callback-plus-drain deadline; uncertainty blocks without retry or automatic termination. A peer timeout receives a labeled receipt-based local cutoff, not a claimed remote deadline; dequeue and view replacement never reset it. Stop gets a separate five-second observation budget, after which unresolved work remains blocked rather than being declared stopped.
4. Retain exact remote open IDs for the life of one connection, up to 65,536 unique IDs of at most 200 UTF-8 bytes each. An ID is never readmitted, including after its diagnostic record is evicted. A separate 256-entry content-free diagnostic ring is not an interaction quota. Exhausting the explicit identity budget stops further admission and requires deliberate safe connection renewal after settlement/exit; never wrap or silently evict replay protection. This high but finite exceptional limit is preferable to unbounded memory or probabilistic replay rejection, and must be visible and boundary-tested.
5. Host UI IDs, one-shot adapter reply tokens and current runtime/view generations provide at-most-one local reply attempt, not authenticated extension provenance or remote exactly-once delivery. All form/feedback content is literal presentation and subject to existing credential-like content rejection before projection. Tool authorization remains a distinct path; confirming a generic form never grants tool permission. The current message contract defines exact DTOs, text-feedback retention and covered custom-tool policy.
6. Track a separate pending handler lease for exactly dispatched, current-catalogue extension slash commands. Installed 0.86.1 source behind the public RPC operation establishes that the matching prompt response follows awaited handler settlement, including rejection that is caught and separately emits extension_error. This is version-pinned evidence, not a cross-version RPC promise or proof of successful execution, detached-work completion, or agent quiescence. Ordinary prompts/templates/skills retain the existing admission-versus-agent-settlement distinction. Errors are projected independently; abort ACK cannot release the command lease. Runtime replacement still requires owned-child exit, and Stop-incompatible operations are not made compatible by automatic termination.
7. The integrated intents/projections migrate Webview protocol version 2 to version 3. Reject obsolete frames and resynchronize a recreated view; do not describe current v2 consumers as v1, mix envelopes, or add a compatibility shim that accepts stale authority.

Evidence and qualifications: [target research and executed probes](../archive/2026-09-27-wi-013-target-research.md); the exact installed command dispatch chain is recorded in dist/delegated-completion-20260928/wi013-command-semantics.txt (public rpc.md and extension declarations; release implementation rpc-mode.js → agent-session.js → awaited registered handler). Ownership-loss feasibility is not yet a selected production persistence/admission design. No application behavior, gate or WI is accepted by this section.

## Accepted ownership-loss recovery boundary

The agent selects a passive exact-child supervisor and a persistent admission fence. A memory-only reload barrier cannot survive the event it is meant to guard. A marker without an independent observer can prohibit work but cannot positively recover after host loss. PID polling and user assertions are not exit witnesses; automatic kill-on-disconnect would change the confirmed Stop compatibility rule. The separate Windows public-runtime spike establishes independent observer feasibility, not a complete implementation.

**Recovery domain and tradeoff:** use the extension's actual globalStorageUri directory as the local recovery domain, with one admitted Pi runtime at a time across windows sharing that directory. This is an explicit conservative product restriction for this personal Windows target, not a machine-wide mutex, terminal-session lock or sandbox. A second window shows the occupied/unknown-runtime reason and does not spawn. It avoids inventing a stable window identity, workspace-switch escape or an unverified multi-owner recovery registry. Independent concurrent runtimes in the same storage domain are not supported by this slice; other VS Code profiles/installations/terminal processes are outside this ownership boundary. The restriction and recovery consequences must be visible before trusted loading and in startup failure UI. This is a delegated product/architecture choice, not a claim that the maintainer personally chose or tested it.

**Owners and storage:** host owns admission and explicit recovery; adapter owns public RPC mapping; a packaged independent Node supervisor directly spawns and retains the exact pi child. Only fixed lifecycle metadata is stored under globalStorageUri/recovery-v1: schema version, fresh run/host/supervisor/child identities, timestamps, disposition and observed exit code/signal. No provider configuration, credentials, prompt, answer, extension source, transcript or session-file contents. Fixed records are at most 4 KiB each. The host exclusively creates and flushes the fence before launching; the supervisor alone publishes the matching terminal receipt. A host-only crash is in scope, not power-loss durability, disk corruption, malicious same-user tampering or simultaneous observer loss. Never accept malformed, oversized, version-mismatched or wrong-run receipts; inability to persist the fence prevents spawning. Missing/uncertain evidence remains blocked, not automatically expired or evicted. Retain only the current run plus at most 16 resolved content-free diagnostics after safe retirement; unresolved evidence is never removed for capacity.

**Loss and termination:** on owner loss, revoke product transport/answer admission but retain exact-child observation; drain/discard bounded output without closing pi stdin as a covert termination mechanism. Never auto-kill on a Stop deadline or compatibility failure. Offer a separate explicit “End owned runtime” action with irreversible-work warning, routed only to the retained owner capability (not an arbitrary PID or shell command). It may request SIGTERM and, after five seconds without exit, SIGKILL; another five-second deadline leaves termination unconfirmed. Observe the child's exit separately from stream close; descendants may retain pipes. Neither signal delivery nor transport loss proves exit. The receipt identifies actual retained-child exit or positively established never-spawned initialization failure. Exit does not prove descendant termination, rollback or successful command completion.

**Recovery:** a matching terminal receipt and deliberate recovery are both required after uncertainty. “Recover controlled execution” retires only that exact run and creates fresh runtime/view/reply identities, clears temporary grants and interaction state, preserves the host's available draft/dialogue, and never replays a task or silently reloads trusted extensions. A full host crash still loses memory-only unsent draft; this feature does not add draft persistence. Normal user-confirmed idle profile/session replacement can retire a cleanly observed predecessor as part of that already-explicit action. Reload alone, PID absence, a new ready process or a user's assertion does not retire an uncertain fence. If the supervisor dies before persisting evidence, recovery remains unavailable; display that limitation honestly rather than providing a “clear unknown” bypass. Storage deletion/uninstall is not an in-product recovery action.

The bounded design and exact DTO/coverage contract are accepted under delegation. The acceptance record separates deterministic crash-window/storage/receipt tests from actual pi, target, same-domain second-window, observer-loss, explicit termination/recovery, native F5 and installed-package evidence. No broad gate is closed by this scoped decision.

Primary capability references: [VS Code storage capabilities](https://code.visualstudio.com/api/extension-capabilities/common-capabilities) establishes globalStorageUri as extension-owned storage accessible across workspaces; [Node child-process documentation](https://nodejs.org/api/child_process.html) distinguishes detached lifetime and exit/close. These APIs do not prove the selected storage protocol or shipped recovery behavior; local evidence is linked in the target investigation.

## Selected idle profile-restart checkpoint

Installed validation exposed pi 0.86.1's deferred persistence: a fresh session has an identity/path but is not persisted until an assistant entry exists. Do not weaken resume identity checks, force synthetic messages, or inspect session files. Before changing the execution profile, the adapter performs public get_state → get_session_stats → get_state, each bounded to five seconds. Verify exact current identity/path, idle/no-pending-work state and stable active-branch message count; validate nonnegative safe statistics counts. Statistics count all entries and are not equated with the active branch after compaction. A never-resumed, untouched conversation with both counts zero can be replaced as a new empty conversation; unsent host draft survives. A previously verified saved resume or positive assistant-entry count retains strict id/path resume. Nonempty unpersisted or uncertain state rejects the switch before retirement, retaining the old ready runtime and draft. It requires no content-sized get_messages response, avoiding a history-volume failure during an otherwise idle profile switch. This conservative rejection is preferable to silent loss; it does not promise preserving third-party private in-memory state across restart. This is a delegated corrective choice; revised-package and native F5 evidence are linked in the acceptance record.

**Upstream initialization limitation:** pi 0.86.1 public RPC awaits extension binding before attaching its stdin JSONL reader (installed rpc-mode.js). An extension that awaits a UI answer inside session_start is therefore not generally serviceable through that startup sequence; an actual isolated no-handler probe observed child exit rather than successful readiness. Do not claim that pausing the adapter's human-wait accounting repairs this upstream ordering. The selected real target only emits startup status and invokes its required forms from registered commands. Preserve that verified target scope, report failed readiness honestly and retain the ownership/recovery evidence; do not patch private pi startup internals or synthesize a successful answer. This is an explicit compatibility limitation and failure path, not a reduction of the selected target's required workflows.

## WI-008 delegated recovery correction — scoped acceptance

Actual clean-profile verification on September 28, 2026 exposed that a newly created pi session can have an identity but no persisted file, even when no model is configured. After observed owned-child exit, resuming that untouched identity fails strict identity verification. Under the existing delegation, choose a narrow host-owned fact: a newly started **controlled**, non-resumed conversation with no admitted user submission may be replaced by a new empty conversation during deliberate controlled recovery. Model setting changes alone do not turn it into a submitted conversation. Retain the draft; do not replay it. Trusted, resumed, submitted or otherwise uncertain conversations retain strict resume behavior, with no fallback after resume failure. This adds no session-file access or persistence claim and does not relax the terminal-receipt requirement. This narrow correction was evaluated under delegation on September 28, 2026: public-seam regression tests and actual native F5/installed clean-profile evidence under dist/delegated-completion-20260928/wi008-readiness-native/ and wi008-readiness/ establish the untouched empty recovery. Submitted or uncertain missing-file cases still have no resume fallback; explicit New conversation uses its existing loss disclosure. WI-008 overall acceptance remains in ACTIVE; earlier accepted scope remains bounded by its existing archive.

## WI-010 delegated cleanup correction — limited acceptance

On 2026-09-28, actual native trust revocation exposed a host guard that advertised End/Recover but refused both when workspace execution was ineligible. Under the existing delegation, distinguish **cleanup authority over the retained exact run** from **authority to start workspace execution**. Permit explicit native-confirmed End and matching-terminal-receipt recovery in restricted/no-folder/multi-root states. Keep generation/view validation, the separate deliberate recovery action and all receipt rules. Recovery does not grant workspace trust, choose resources or start an ineligible runtime; normal startup eligibility and fresh resource choice still apply. Requiring the user to trust untrusted content merely to stop an already owned child was rejected. Automatically killing on trust revocation was also rejected because it contradicts the accepted owner-loss contract.

The agent evaluated this correction under the delegation, not as a personal maintainer inspection: two public host-seam regressions failed before the guard fix and passed afterward; the standard suite is 665/665, compile/lint pass. Actual Code 1.139.1 isolated installed VSIX and official Code 1.105.1 native F5 both exercised active-stream Don't Trust, blocked admission, explicit End with actual child exit, separate Recover without runtime startup, native Trust, fresh resource choice and covered-tool approval after both allow/decline. Evidence: dist/delegated-completion-20260928/wi010-installed/ and wi010-native/, trust-report.json and run-trust-fixed.log; the current package is wi013-package/pi-vscode-wi010-restricted-cleanup.vsix. Incorrect early auto-exit expectations and the actual product failure are retained separately. This correction alone does not accept any broad gate.
