## 1. 这份说明怎么用

这份文档为 Pi 的界面建立一套稳定的称呼。介绍产品时使用中文区域名；讨论设计或提出修改时，进一步指出组件与状态；找代码时查看最后的实现映射。英文名称便于在设计稿、Issue 和技术沟通中使用，不要求界面把这些名称全部显示出来。

和维护者对着界面说话时，优先用[界面名词说明](plugin-parts.zh.md)里的日常叫法和编号截图。底部卡片叫**消息编辑区**，不要叫作曲区；从芯片或盾牌打开的卡片叫**模型选择器**或**执行配置**，不要叫弹出层。

**界面整体名称：Pi 聊天侧栏（Pi Chat Sidebar）。** 它显示在 VS Code 的侧栏中，首选右侧辅助侧栏。VS Code 自己的活动栏、编辑器标题栏及窗口标题栏属于宿主界面；其中打开 Pi 的入口图标不属于 Pi 会话导航栏。

可以直接使用这段介绍：

> Pi 的聊天侧栏由会话导航栏、会话内容区、任务状态与操作区，以及底部消息编辑区组成。用户可以在输入工具栏中添加上下文，并通过模型与推理设置入口选择模型、调整推理强度，也可以查看当前权限。历史会话面板与编辑区设置页分别提供会话管理和配置入口。

这里的“四个区域”是功能划分，不表示屏幕上永远存在四个有边框的矩形。任务状态与操作区按需显示，欢迎区和历史会话面板则对应中部内容的不同状态。

## 3. 四个主区域

### ① 会话导航栏 — Session Navigation

**位置与作用：** 位于 Pi 自有界面顶部，帮助用户知道“当前在哪个会话”，并进入会话管理和设置。

| 组件名称 | 当前内容与职责 |
|---|---|
| 当前会话标题 | 显示当前会话名称；长名称受可用宽度约束 |
| 历史会话按钮 | 打开或收起历史会话面板 |
| 新建会话按钮 | 发起新会话操作，沿用既有会话切换与确认流程 |
| 设置按钮 | 打开编辑区设置页 |

它可以简称“导航栏”，但不建议简称“标题栏”：VS Code 也有自己的标题栏，容易指错位置。设置按钮属于导航栏，打开后的编辑区设置页是独立辅助界面。

**介绍示例：** “顶部会话导航栏用于新建会话、浏览历史和打开设置。”

### ② 会话内容区 — Conversation Area

**位置与作用：** 位于导航栏下方，是阅读空间，呈现用户与 Pi 的交流内容，以及随回复产生的活动信息。

主要内容包括用户消息、助手回复、Markdown 代码块、消息内活动摘要及其展开详情。活动详情可显示上游提供的思考信息、工具参数与输出；它不是对模型完整内部推理过程的保证。恢复已有会话后，历史消息内容也在这里阅读。

这个区域有几种常见显示状态：

| 状态 | 推荐称呼 | 内容 |
|---|---|---|
| 尚无消息 | 欢迎区／欢迎空状态（Welcome State） | 三色 Pi 标志与一句问候；标志支持重播动画 |
| 已有消息 | 消息列表（Message List） | 用户与助手的消息，按会话顺序排列 |
| 正在生成 | 流式回复（Streaming Reply） | 助手回复随内容到达逐步显示 |
| 展开消息活动 | 活动详情（Activity Details） | 与该消息关联的工具、思考、执行状态及输出 |
| 连接或运行异常 | 状态提示／错误提示 | 当前无法正常显示或继续工作的原因与可用恢复入口 |

**欢迎区属于会话内容区的一种状态，不是第五个固定区域。** Pi 标志称为“欢迎标志”或“品牌标志”；正文旁的小操作图形才通常称为“图标”。

**介绍示例：** “中部会话内容区展示交流记录，工具执行详情可以按需展开。”

### ③ 任务状态与操作区 — Task Status and Actions

**位置与作用：** 通常位于消息编辑区上方，按需承载当前任务的进展反馈，以及需要用户处理的操作。它没有必要一直占据空白高度。

| 子组件名称 | 用户在这里做什么 | 说明 |
|---|---|---|
| 任务状态提示 | 查看工作中、回复中、重试、压缩上下文、完成、停止或失败状态 | 它是状态反馈，不是精确百分比进度条 |
| 工具审批卡片 | 查看操作及作用范围，作出允许或拒绝决定 | 这是执行前审批，与事后修改审阅不同 |
| 修改审阅面板 | 查看已发生修改的摘要，打开捕获的前后内容对比或源文件 | 不代表等待应用的补丁，也不提供自动回滚承诺 |
| 交互请求面板 | 回答扩展发出的选择、输入等请求 | 取消单个交互不等于停止整个任务 |
| 运行恢复提示 | 处理需要显式介入的运行状态 | 与普通任务 Stop 分开理解 |

这个区域与消息里的活动记录相关，但用途不同：**活动记录用于阅读“发生了什么”，任务操作用于处理“现在需要我做什么”。** 全局连接／运行错误也可能出现在会话内容区，不能把所有错误提示都理解成底部的一个固定控件。

**介绍示例：** “需要审批或恢复时，任务操作区会显示对应入口，用户可以在继续工作前查看操作范围。”

### ④ 消息编辑区 — Message Composer

**位置与作用：** 位于底部，把草稿、附件和发送相关控件组织成一组。对外推荐叫“消息编辑区”；代码和设计沟通中可使用 Composer。历史文档里的“作曲区”指同一区域，不是另一个功能。

| 子区域／组件 | 英文名称 | 作用 |
|---|---|---|
| 上下文附件区 | Context Attachments | 展示显式添加的文件／选区及状态，提供移除、确认、预览等操作 |
| 消息输入框 | Message Input | 编辑多行任务描述或问题 |
| 输入工具栏 | Composer Toolbar | 输入框下方的紧凑操作行 |
| 添加上下文按钮 | Add Context Button | 工具栏里的「＋」，打开添加文件／选区等操作菜单 |
| 模型与推理设置入口 | Model and Reasoning Settings Trigger | 显示格式化后的模型 id 与思考强度，并打开模型选择器 |
| 权限入口 | Permissions Control | 查看当前权限说明及已有会话授权，按支持的操作撤销授权 |
| 发送／停止按钮 | Send / Stop Button | 在同一位置根据任务状态切换主要操作 |

“输入框”只指可编辑文字的部分；“消息编辑区”包含它周围的附件和工具栏。“输入工具栏”也不同于顶部会话导航栏：前者服务于消息与任务，后者服务于会话管理。

发送和停止共享位置，但含义不同。Stop 是请求停止当前任务及排队续行，不会撤销已经完成的副作用。未打开文件夹或尚未作出项目资源选择时，用户可以准备草稿或选择全局默认模型；能够编辑不等于任务已获准执行。

**介绍示例：** “底部消息编辑区集中提供任务输入、上下文选择、模型设置与发送控制。”

## 4. 三类辅助界面

### 历史会话面板 — Session History Panel

由历史会话按钮打开，占据中部内容空间。当前正式实现提供当前项目的已保存会话列表、标题、修改日期、当前会话标记、刷新及分页，并显示加载、空列表和错误状态。选择会话进入既有恢复流程；返回后继续阅读当前会话。

**历史会话面板是“选哪个会话”；历史消息是“这个会话之前说了什么”。** 它们分别对应会话目录和会话内容。附件历史则是另一类上下文记录，不能混称为会话历史。可搜索历史列表目前存在于独立样板，不应作为当前正式面板的已实现功能介绍。

### 设置弹层与操作菜单 — Popovers and Menus

这类界面从某个触发按钮旁展开，用于局部选择或操作，通常不取代整个主界面。

- **操作菜单（Menu）**：列出可执行动作，例如「＋」展开的添加上下文菜单。
- **设置弹层（Popover）**：容纳一组局部设置，例如模型与推理设置弹层。它可以包含模型选项和滑条，不必把整个容器都叫“下拉框”。
- **模型选择器（Model Selector）**：选择使用哪个模型的控件。
- **推理强度滑条（Reasoning Effort Slider）**：调整所选模型支持的推理档位。轨道（Track）、滑块（Thumb）和档位刻度（Stops）分别是滑条的三个可描述部分。

当前三色渐变与最高档流水属于推理强度滑条的视觉反馈。它表达所选强度，不表示模型此刻正在计算。支持的档位取决于模型能力，介绍时不应固定说成“五档”。启动前默认模型包装组件与运行会话包装组件共用 `ModelPickerView`，包含上游支持档位的强度滑条。准备阶段按模型保存 pi 默认值；运行会话仍区分已应用与下一轮待生效设置。

### 设置页与确认对话框 — Settings Page and Confirmation Dialogs

对话框提供相对独立的任务空间，适合配置、确认或恢复流程。当前示例包括：

| 对话框 | 内容 |
|---|---|
| 编辑区设置页 | 通用／语言、默认模型、供应商详情与插件清单；执行配置位于输入区权限展开层 |
| 项目设置对话框 | 显式选择是否使用项目本地 pi 设置和资源，完整说明可展开 |
| 打开文件夹提示对话框 | 当前操作需要文件夹时提供恢复入口，并保留草稿 |

介绍时可以把设置称为“配置入口”，但不要把其中所有项都叫“全局持久设置”：例如当前界面语言在宿主内存共享，宿主重启后恢复默认。项目资源同意、工具审批和执行配置也有不同作用范围，准确语义见[领域词汇表](../../CONTEXT.zh.md)。

输入 API Key 时实际出现的是 **VS Code 宿主密码输入框**，不是 Webview 内的密钥表单。介绍这一功能时可以说：“从供应商设置发起，通过 VS Code 的密码输入框录入。”

## 5. 常见说法如何换成准确名称

| 含糊说法 | 建议说法 | 适用场景 |
|---|---|---|
| 最上面那排按钮 | 会话导航栏中的历史／新建／设置按钮 | 调整顶部布局 |
| 中间那个 Pi | 欢迎区的 Pi 品牌标志 | 讨论大小、配色或入场／重播动画 |
| 下面那个框 | 消息编辑区；若只指文字部分则说消息输入框 | 讨论容器还是输入内容 |
| 输入框下面一排 | 输入工具栏 | 调整控件间距和对齐 |
| 模型条／颜色条 | 模型选择器／推理强度滑条 | 区分模型与强度 |
| 那个弹窗 | 模型设置弹层／编辑区设置页等具体名称 | 明确触发来源和任务 |
| 历史记录 | 历史会话面板／已恢复历史消息／附件历史 | 区分记录的对象 |
| 确认修改的地方 | 工具审批卡片或修改审阅面板 | 区分执行前授权与执行后检查 |

描述修改时，使用 **“区域 + 组件 + 状态 + 期望”** 会更容易定位。例如：

- “消息编辑区的输入工具栏，在 280px 宽度下，模型名称不要挤压发送按钮。”
- “模型与推理设置弹层里的推理强度滑条，只在最高档播放向右流水。”
- “历史会话面板加载失败时，错误说明和刷新入口需要同时看得见。”
- “欢迎区的 Pi 标志点击后重播动画，播放期间再次点击不重启动画。”

## 6. 演示时的讲解顺序

建议按用户的一次任务来介绍，比逐个列按钮更容易理解：

1. **认识侧栏：** 指出顶部会话导航栏、中部会话内容区和底部消息编辑区；说明任务操作按需出现。
2. **准备任务：** 在消息输入框写任务，通过「＋」选择文件／选区；从模型入口选择模型，查看可用推理档位。
3. **观察执行：** 发送后阅读流式回复和活动详情，需要审批时在任务操作区查看范围并决定。
4. **查看结果：** 阅读回复；有可审阅修改时打开修改审阅面板查看捕获的差异。需要中断时使用停止按钮。
5. **管理会话与配置：** 打开历史会话面板说明恢复流程，再打开设置页说明供应商和默认模型；执行配置从输入区权限入口说明。

演示当前代码时，应按实际出现的控件和可用状态讲解；参考样板中的搜索或候选布局不作为正式功能展示。上述名称是讲解辅助，不取代产品验收。

## 7. 界面名称与当前代码的对应关系

界面区域不等于独立代码模块。当前正式入口和预览共用 [candidate.tsx](../../src/webview/chat/candidate.tsx) 中的组合组件，`Candidate` 是原型阶段保留下来的名称，并不意味着它只用于预览。

| 界面区域 | 当前代码入口 | 拆分现状 |
|---|---|---|
| 侧栏整体／会话导航栏 | [candidate.tsx](../../src/webview/chat/candidate.tsx)、[session-navigation.tsx](../../src/webview/chat/session-navigation.tsx) | 页面负责共享状态与跨区域焦点；导航负责其控件和设置意图 |
| 会话内容区 | [candidate-conversation.tsx](../../src/webview/chat/candidate-conversation.tsx)、[reply-markdown.tsx](../../src/webview/chat/reply-markdown.tsx)、[candidate-conversation.css](../../src/webview/chat/candidate-conversation.css) | 消息／活动、Markdown 与其样式已独立，滚动容器与空状态仍由主组件管理；消息行不显示说话人标签，无活动的回复不再显示占位说明 |
| 欢迎区 | [pi-welcome-mark.tsx](../../src/webview/chat/pi-welcome-mark.tsx) | 标志动画已独立；问候语及欢迎布局仍在主组件 |
| 任务状态与操作区 | [task-status.tsx](../../src/webview/chat/task-status.tsx)、[change-review.tsx](../../src/webview/components/change-review.tsx)、[approvals.tsx](../../src/webview/components/approvals.tsx)、[extension-interactions.tsx](../../src/webview/chat/extension-interactions.tsx) | 状态行、审批、审阅、扩展交互与恢复提示各自就近维护；区域组合、显示条件与跨区域高度预算仍在主组件 |
| 消息编辑区 | [message-composer.tsx](../../src/webview/chat/message-composer.tsx) | 负责输入高度、输入交互、工具栏、权限与发送／停止，接收页面快照及客户端意图 |

样式由 [styles.css](../../src/webview/styles.css) 汇入，既有组件样式，也有集中在 [candidate.css](../../src/webview/chat/candidate.css) 的区域样式。[message-composer.css](../../src/webview/chat/message-composer.css) 负责输入、工具栏、上下文及权限表面，共享高度预算仍由页面管理。[candidate-conversation.css](../../src/webview/chat/candidate-conversation.css) 负责消息行、Markdown、代码块与工具活动记录的呈现。任务状态与操作区的样式就近拆分：[task-status.css](../../src/webview/chat/task-status.css) 负责状态行标记与动效，[candidate-approvals.css](../../src/webview/chat/candidate-approvals.css) 负责审批卡片内部布局，[candidate-review.css](../../src/webview/chat/candidate-review.css) 负责审阅面板，[extension-interactions.css](../../src/webview/chat/extension-interactions.css) 负责扩展交互表单、反馈与恢复横幅；跨区域 `:has()` 高度预算仍集中在 candidate.css。确认对话框壳与输入区执行控件样式分别在 [chat-dialog.css](../../src/webview/chat/chat-dialog.css) 与 [interface-settings.css](../../src/webview/chat/interface-settings.css)。状态和宿主通信由 [webview-client.ts](../../src/webview/webview-client.ts) 等文件承担，不属于可见的第五个区域。

[session-navigation.css](../../src/webview/chat/session-navigation.css) 维护导航布局和导航／历史共享图标按钮反馈；[candidate-sessions.css](../../src/webview/chat/candidate-sessions.css) 维护历史面板布局及当前行、焦点、禁用状态。[session-icon.tsx](../../src/webview/chat/session-icon.tsx) 使用本地官方 Lucide 几何；来源与许可保留在 assets/icons/lucide。当前行的勾选标记独立于悬停与键盘焦点，完整标题保留在可访问名称和悬停提示中。

本轮浏览器对照入口为预览服务器的 `/navigation-review.html` 与 `/settings-review.html`：同屏 280／320／400px，可切换主题、中英文及各区域夹具，实际挂载共用聊天组件与合成宿主，不是 F5 或安装包证据。

因此，讨论界面时优先使用本文的区域名称；定位实现时再使用现有文件名。本文不要求立即重命名或重构。以后若调整区域归属或用户可见功能，应同时更新本说明及对应代码映射；颜色、间距和动画参数仍由 [pi-sidebar-ui skill](../../.agents/skills/pi-sidebar-ui/SKILL.md) 管理。

附件列表、预览和历史的内部样式现由 [candidate-context.css](../../src/webview/chat/candidate-context.css) 维护；CandidateContext 分别记录预览与历史的返回焦点。列表用发线分隔，路径披露与关闭复用官方 Lucide；阅读标题可钉住，快照原文先于完整限制说明显示。附件内容仍局部滚动，输入／Stop 在滚动区外。第六轮可查看 `/consistency-review.html` 三宽度合成预览；此入口不是真实宿主验收证据。
