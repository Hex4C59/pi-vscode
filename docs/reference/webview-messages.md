Do not reuse ordinary prompt occupancy: queue ACK cannot release the active task. A task that settles before write refuses that attempt; no implicit idle prompt. Timeout enters existing uncertain-runtime recovery, never a fresh unbounded wait or retry.

Translate matching public user `message_start` only after validating text content; correlate multiplicity within this live session. ACK, queue removal and consumption remain separate facts. External/unattributed entries remain visibly unattributed; do not claim they were sent by this UI. Unknown/malformed/oversized data cannot fabricate an empty queue or recalled success; fail closed with fixed diagnostics and no text in logs.

Reserve lossless recovery capacity before destructive clear from the bounded observed snapshot; capacity/unattributed-data gaps refuse explicit recall. Stop may not silently drop recovery on capacity failure: expose unconfirmed Stop and existing safe recovery. Validate clear's arrays before recording confirmed recall. An empty `queue_update` during clear does not mark those texts consumed. Retain confirmed clear output before abort so later abort failure cannot erase it. A clear timeout keeps local text unknown; late old-session replies never mutate the replacement.

Disconnect retains this generation's local recovery with unknown facts; New/Restore/profile/resource replacement adds the PRD loss warning and clears only on committed handoff. ## Endpoint write transaction (WI-038, accepted contract)

The host `models` module owns a lock adjacent to the canonical `models.json` parent directory, `.models.json.pi-vscode.lock`, and all transaction temporary files. Add/remove acquire it once before reading and hold it through merge and atomic replacement; contention fails immediately without queuing or automatic retry. The lock contains only a random ownership token and PID, never configuration text or credentials. Parent-directory aliases share the lock; linked or otherwise ambiguous target-file identities are refused.

The internal result distinguishes `committed`, `not-committed` with a fixed reason, and `committed-cleanup-failed`. Only a clean committed result continues model reload and login/logout. Contention, detected revision conflict, invalid input/file, serialized output over the 1 MiB read budget and write failures produce bounded fixed `providerConfigState.error` text. Cleanup failure carries whether replacement occurred; a committed cleanup failure explains that the endpoint was saved/removed but credential actions were not continued. No raw exceptions, private paths, lock metadata or configuration content reach the Webview. Refresh reads current state; retry is explicit and does not replay an uncertain mutation. Existing cancelled API-key collection can still leave a cleanly committed endpoint.

Before replacement the host compares the original file bytes and identity (or missing state) to a fresh read. A mismatch refuses replacement and preserves the external version. External writers that do not participate in the lock protocol can race this check and rename; this is not filesystem compare-and-swap or universal external-write protection. Lock release removes only the current transaction's matching lock; failure preserves the barrier. Crash leftovers are never removed based on age or PID. Recovery requires closing all relevant writing hosts and maintainer verification before manually removing the confirmed leftover lock. There is no renderer unlock/delete capability. Webview v3, endpoint intent fields and secret ownership stay unchanged. The accepted decision and evidence live in [ADR 0007](../decisions/0007-endpoint-write-transaction.md) and the [WI-038 acceptance record](../archive/2026-09-30-wi-038-macos-acceptance.md).

## Runtime protocol failures (WI-033)

The adapter decodes only consumed event fields before any activity, final-message or tool-completion projection. Recognized malformed message/content, tool-result, retry or compaction fields produce a fixed protocol error and revoke the connection. Content arrays preserve indexes for undisplayed image/toolcall/unknown object types; empty arrays and extra upstream metadata remain valid. Unknown event/update types, empty lines, non-JSON and non-object input retain ignored handling. Extension dialogs, approval envelopes and feedback keep their existing validators and rejection policies.

Pending RPCs bind both ID and command. A matching response must have the expected command and boolean `success`; unknown, duplicate and retired IDs are ignored. Internally, validated responses are separate from protocol-error, disconnected and timeout results. Command-specific `data` stays with existing domain parsers. A valid `success: false` remains an upstream rejection; malformed acknowledgement cannot invent readiness, applied settings, successful Stop or remote prompt rejection.

A protocol fault synchronously retires transport/answer authority, settles pending calls and clears their timers/listeners through the existing uncertain-runtime release. No partial projection from the bad event, automatic termination or task replay follows. A written prompt without valid acknowledgement remains delivery-unknown. Stop cannot succeed because fault cleanup reset occupancy. Detachment discards the remaining lines in the current stdout chunk as well as future old-connection frames. UI receives only the bounded fixed error and existing runtime-failure projection; no raw bad payload is exposed. Host lifecycle and Webview v3 interfaces are unchanged.

## Controlled execution contract

Execution actions use the envelope rules above and these inbound shapes:

- `stopChat`: `{ version: 3, type: "stopChat", generation: number, viewId: string }`; only an active chat not already stopping is acted on.
- `decideApproval`: `{ version: 3, type: "decideApproval", generation: number, viewId: string, id: string, decision: "once" | "session" | "deny" }`.
- `revokeGrant`: `{ version: 3, type: "revokeGrant", generation: number, viewId: string, id: string }`.

### Ownership, eligibility and bounded capture

`DraftSubmission` owns the host draft, attachment preparation and submission ledger; `PiChatViewProvider` supplies execution eligibility and coordinates runtime/Stop/session transitions. `runtimeLifecycle.ts` owns the narrow internal prompt/result contract; adapter owns encoding, correlation and bounded writes; Webview owns presentation only. - Add uses the native multi-file picker; selection Add captures one explicit nonempty selection. No inferred open-file attachments. This acquisition ceiling allows common UTF-16/UTF-8 decoding overhead for a 256 KiB text snapshot; it is not the attachment budget. Reuse an already-open matching TextDocument (including dirty text) even if disk is larger, but still require existing regular-file containment. Before `getText()`, use `offsetAt` at the last line end to reject over **262,144 UTF-16 code units** without allocating the entire text; then enforce **262,144 UTF-8 bytes** on captured text. For unopened files, VS Code owns decoding/loading; its public API offers no hard read quota against concurrent file growth. ### Draft transaction, delivery and lifecycle

1. Host owns acknowledged body and attachment across view recreation. New view gets fresh `viewId` and current revision before editing; local newer unacknowledged text is not overwritten by an old acknowledgement. UI clears only on `lastSubmission.draftRevision` matching the submitted revision **and** unchanged local edit sequence; new edits are subsequently synchronized as a new revision. Changes during preparation invalidate its token and preserve the newer draft. An edit never received by host cannot be promised after view loss; UI labels synchronizing/unsynchronized state and does not claim it is saved.
2. Serialize one picker/preparation and one submission. Capture preparation token, draft revision, workspace generation, runtime session and current view. Perform bounded async source checks; recheck every identity after awaits. At final synchronous boundary verify document object/version/open status/text/dirty flag, body/attachment budgets, metadata, eligibility and cancellation token; reserve history capacity, construct one immutable submission, serialize and validate the actual outbound frame **before admission**. No asynchronous file reread after freezing. This guards host/editor consistency, not future runtime tool reads or check/use races.
3. Admission atomically commits the immutable snapshot plus body, advances/clears only that draft revision and marks delivery `host-accepted`; history and prompt take the same frozen data. Call the adapter immediately within the same synchronous turn; adapter checks expected session and consumes its one-attempt token before handing bytes to stdin. `write-attempted` is published at that boundary, `rpc-accepted` only on matching successful response, `rpc-rejected` only on an explicit negative response, `not-sent` only when no write was attempted, and `unknown` on write/ACK/loss uncertainty after an attempt. No reinsertion of a possibly sent draft and no automatic resend. Keep even rejected/uncertain submitted snapshots for inspection, accurately labelled—not all are “sent successfully”.
4. Task outcome is independently `pending | settled | failed | interrupted`; matching `agent_settled` is the existing settlement boundary, not the prompt ACK. Early streaming/settlement before ACK must not regress outcome or allow a second admission while ACK remains unresolved. Host acceptance or write/drain is not remote acceptance/completion.
5. Stop during picking/preparing invalidates token, yields `preparation-cancelled`, preserves draft and guarantees zero prompt writes. After write handoff, use existing controlled Stop/clear_queue/abort; remote effects may already exist. Stop never sends drafts, restores uncertain submissions or replays them. View disposal cancels uncommitted picker/preparation/preview but preserves acknowledged draft and admitted history; a committed attempt continues host-owned. Old-view events cannot mutate the replacement.
6. Workspace/trust/eligibility or runtime replacement invalidates attachment eligibility and async work; retain body with an invalidation notice, remove source capability, require deliberate reattachment, and never silently carry context to another project/runtime. Live history ends only with its owning session: disclose memory-only loss on deliberate restart/resource-choice change; fault loss reports history ended, not persistence. Host reload/provider disposal releases all snapshots, subscriptions, timers and preview references. A same-session successful Stop retains history. No new session persistence or automatic reset.

**Delivery/settlement recovery:** an explicit RPC rejection ends the waiting execution state as failed and offers configuration inspection before a deliberate new submission, not an unavailable Stop action. If settlement precedes the ACK, admission remains blocked until the ACK resolves, then the same settlement projection completes the turn. A late ACK cannot overwrite runtime-failure/interrupted state. A valid Stop received after settlement still republishes current state so a renderer cannot remain locally stuck in stopping.

### WI-016 T016-01 — Dirty-editor write protection

Host policy checks built-in `write` and `edit` targets before offering an approval and again before allowing either a one-call decision or an exact live-session grant. It reads VS Code document metadata and filesystem identity, not buffer contents; it never saves a document. If the target has unsaved editor changes, the call is denied and the existing bounded `chatError` field tells the user to handle those changes and explicitly retry. An unreliable check also denies with a fixed recovery message. No new Webview capability or gate-envelope field is added.

The target mapping follows declared pi 0.86.1 write/edit path resolution (relative/absolute, one leading `@`, home, file URL, Unicode spaces, and native-Windows shell drive spellings). Existing files use canonical path / file identity; missing files use a canonical existing ancestor. The document set is rechecked after asynchronous resolution, with at most three attempts on churn. Non-file/closed documents are excluded. Unrelated dirty files do not prohibit clean targets or reads. Approving a call that became dirty while waiting creates no new session grant; existing grants do not bypass protection. Cancellation and grant revocation during a final check cannot revive authorization.

This is a public `tool_call` pre-execution check, **not an atomic lock** between an editor and a later filesystem write. Edits after the final check, opaque shell writes, trusted-extension execution and concurrent filesystem changes remain outside a complete-protection guarantee. pi still owns tool execution and cancellation. The UI shows a reason for the denied call; no retry, rollback or auto-save is performed. Current tests and native evidence belong to ACTIVE, not an implied REQ-007 review-diff completion.

### WI-016 T016-02 — Already-applied change review (contract)

This implements the Goal-approved REQ-007 slice recorded in ACTIVE, not a new PRD/ADR acceptance. Webview sends only v3/viewId/generation named intents: `getChangeReview` (no payload), `openReviewDiff` / `openReviewSource` (opaque host-owned `id`). Unknown/stale IDs cannot open arbitrary paths or commands. Host emits a separate `changeReviewState`; `webviewProtocol.ts` owns its exact DTO. Entries identify tool-reported write/edit targets versus workspace events observed while a task is active. Observation is not agent-only attribution.

Before/after text remains host-owned and is opened via readonly virtual documents in VS Code's native diff editor; no snapshot text, path capability, process, SDK or generic command bridge enters the Webview. Source navigation opens the currently validated source, not an old location promise. Captured historical pairs never become current Git/HEAD diffs and never overwrite source files. Complete/failed/interrupted tool status is separate from observed text differences; errors and Stop may follow partial side effects.

Capture uses approved write/edit's final authorization window for the before image and public tool completion for the after image, independent of bounded activity-display text. Concurrent/preflight-overlapping calls are disclosed, not attributed as isolated operations. The host watches the selected project during tasks for additional change metadata; without a before image it explicitly reports no captured diff instead of inventing one. Safe regular UTF-8 project files only: known sensitive paths/content, external targets, binary/oversized/unreliable reads get a reason, never a truncated or fabricated pair. Capture limitations do not silently approve/deny an otherwise authorized tool; dirty protection and its final recheck remain mandatory.

Technical retention bounds: 128 entries, 256 KiB UTF-8 per text snapshot, 8 MiB retained snapshot text per live runtime, 1 KiB UTF-8 display path, 16 rows per local UI page. No eviction of prior snapshots: entry/snapshot overflow is explicit, and later calls remain subject to normal approval. Reads have bounded size and deadline; late results cannot mutate replacement runtime state. Metadata updates do not reset the selected page or current draft. Snapshots survive view disposal/recreation but clear on runtime/resource/session replacement with an explicit reset notice. Opening a historical diff rechecks the current source and discloses later change/unavailability without changing the captured pair. Native opens are single-flight; repeated intents do not accumulate editor operations. Watcher work is serialized and coalesced by retained path with bounded pending work. Denied final authorization removes provisional captures without consuming retained entries/text. Reset/loss remains visible even when a disconnected runtime hides review actions.

### WI-017 T017-01/02 — Saved-session selection and sequential handoff (contract)

Native host confirmation precedes mutation; restoration requires confirming the other entry point is closed and discloses that confirmation is not an ownership lock. The confirmation also discloses Stop, unsent-draft/attachment loss, memory-only attachment-history loss and clearing grants/review snapshots. Cancel/stale confirmation performs no switch. ### WI-017 T017-03 — Bounded restored history and retained text (contract)

The host restores the public SDK active branch, including available pre-compaction dialogue and generic tool/custom/summary entries, into a separate saved-history projection; it does not duplicate those rows in the live transcript. This presentation does not replace pi's model context. Initial display and each backwards/forwards page contain at most 32 chronological rows, with 4 KiB UTF-8 text per row and explicit truncation/unsupported-content notices. Historical tool names/status describe past records, not currently loaded capabilities or reconstructed success. No historical renderer or extension code executes. Overview/preview projection consumes text segments incrementally rather than joining a complete large record.

The restored public branch's final entry is a host-only anchor. Later pages and previews are re-read through the public SDK and bounded to that anchor, so continuing a conversation cannot shift earlier-page offsets. A missing/noncurrent anchor fails explicitly instead of presenting a different branch. The extension does not add a session-file format, attachment store, global search or branch UI. The helper uses structured bounded requests, a 15-second deadline, 1 MiB response cap and observed child close; neither raw diagnostics nor storage paths reach the Webview.

### Loading, coverage and observable failures

The trusted profile accepts **one explicit local entry file** selected through the native host picker (.ts/.js/.mjs/.cjs); this is an entry, not a promise to sandbox its imports. Verify a canonical regular file and reject known credential/config paths before loading; do not inspect user secrets or install dependencies. Native confirmation identifies the full chosen path and warns about executable initialization, uncovered extension-internal code, single-runtime recovery domain, custom TUI limitations and fresh-consent-on-restart. Cancel/stale confirmation does nothing. The sidebar receives only a bounded display name and profile, never an arbitrary executable path capability. No automatic discovery, download or runtime selection from Webview strings.

Switch only after host tasks, handler lease, dialogs, approvals, model mutations and session operations are idle. Reconstruct the runtime with the current public saved-session identity, preserve available unsent draft/dialogue, clear temporary grants/review/interaction state, and verify public readback before ready. Switch failure remains unready with preserved available draft/dialogue, not automatic fallback/replay. A retry or explicit recovery starts controlled unless a new explicit trusted selection/confirmation is completed. Model/thinking readback, not stale UI, determines the new projection.

Both profiles keep asking for covered tools. Controlled tools retain their existing exact-scope policy. Trusted loading additionally permits **registered custom tools** verified through public getAllTools at the gate boundary, with at most 64 bounded custom names; unknown names and overrides of built-in names deny. Custom calls show complete bounded literal JSON input, “custom extension tool” coverage warning, Allow once and Deny only—no implicit file/shell/session grant or built-in dirty-write guarantee. Existing credential-like/oversized input rejection remains. This adds known custom-tool approval, not an unknown-tool fallback. Trusted executable code and subsequent external effects remain outside a security sandbox; metadata/token correlation does not authenticate hostile extension code. Gate readiness binds profile and runtime; missing/invalid inventory or extension_error during initialization fails readiness even if get_state succeeds. Command errors remain visible despite prompt success.

### Exact interaction-facing DTO direction

All new browser intents use the existing exact-own-fields envelope upgraded coherently to `version: 3`, current `viewId` and nonnegative safe-integer `generation`. New intents are `chooseExecutionProfile { profile: "controlled" | "trusted" }`, `answerInteraction { id, answer }`, `cancelInteraction { id }`, `endOwnedRuntime {}` and `recoverControlledRuntime {}`. IDs use existing opaque 1–100-character host-ID rules. There is no browser file path, remote ID, process PID, SDK call, arbitrary command or recovery-record payload. Answers are exact discriminants: `{ method: "select", optionId }`, `{ method: "confirm", value: boolean }`, or `{ method: "input" | "editor", text: string }`. The host validates method, current active membership, exact option membership and UTF-8 budget before reserving a reply. Empty strings are preserved, not coerced into cancel. Options use host opaque IDs and map to original strings only inside the adapter.

`interactionState` projects an active form or null, queued count, phase (`idle | waiting | blocked`), bounded fixed error code, bounded literal feedback and omitted-feedback count. Forms share opaque id, method, title and an optional explicitly labeled local cutoff timestamp; select adds option IDs/labels, confirm adds message, input adds placeholder, editor adds prefill. Origin is explicitly “trusted runtime extension; not authenticated”, not inferred from a title. No remote-consumed/closed/completed field is fabricated. A separate `executionProfileState` projects controlled/trusted display label, phase (`idle | selecting | switching | recovery-required | error`), fixed failure code and booleans for currently admissible named actions. A separate `providerConfigState` projects non-secret provider readiness, optional auth source labels, default provider/model ids and a bounded model catalogue for defaults; API keys never appear in this projection. A separate `pluginInventoryState` projects busy/error plus at most 64 `{ id, displayName, enabled }` rows (`id` matches opaque host-ID rules; `displayName` ≤512 UTF-8 bytes); remembered paths stay in the host file. Host remains authoritative; Webview state never clears a recovery fence.

Standard feedback is literal: notify, keyed status and string-array widgets are presented; requested terminal title/editor text are displayed as labeled feedback, never executed as title commands or silent draft replacement. Custom/component TUI, editor readback and arbitrary terminal layout remain unsupported and visibly disclosed before loading. Retain at most 16 feedback entries, 65,536 aggregate UTF-8 text bytes and 32,768 bytes per entry; keep at most eight status keys and four widget keys, each key at most 100 bytes. Keyed updates replace their prior entry; clears remove it. Capacity discards oldest feedback with an omission count, never an actionable form/answer. Oversized or credential-like content yields a fixed safe warning, not raw text. Widget placement is a hint only; content remains accessible in the extension feedback region. Feedback is not dialog completion evidence.

### Arbitration, timing and lifecycle

Host coordinator owns one active plus seven FIFO queued forms and current view projection. Adapter owns private remote IDs, exact connection-lifetime replay retention and one-shot reply capabilities. Reserve/invalidate synchronously before any asynchronous write; a later Stop/loss suppresses an unattempted affirmative write, with no retry after uncertain delivery. Host/view/runtime replacement invalidates old answer authority before cleanup. Recreating only the Webview resynchronizes the same host ledger with a new viewId; no timer/request replay. Validation has no side effect on invalid/stale/duplicate input. Declining a form may continue extension code and must be labeled separately from Stop.

Use the selected numeric budgets in ADR 0002. The existing general RPC frame/partial-buffer boundary remains separately enforced; general-stream overflow/loss must not become a fake interaction exit or auto-kill incompatibility workaround. Valid remote timeout duration is finite, nonnegative and at most 86,400,000 ms; larger/invalid duration is an explicitly unsupported request, not silently shortened. Local receipt-based cutoffs invalidate active or queued entries once and cannot prove when upstream expired. A no-timeout form can wait indefinitely for a human. During trusted startup, admitted unanswered forms pause only the remaining 15-second readiness-response budget; after their reply writes finish, that remaining transport budget resumes. This does not infer handler completion or extend the separate Stop observation budget. Reply transport permits at most 16 in-flight writes, shares bounded stream listeners, and requires both write callback and drain within five seconds; capacity or uncertain write failure blocks the connection without retry or automatic termination. A known exact extension-command handler lease has no human-response ACK timer; a five-second bounded write deadline remains. Ordinary prompt transport/admission limits remain distinct. Matching handler response releases only that handler lease; errors, agent work, outstanding dialogs and queues remain independent obligations. An unknown/misformatted slash command is never classified as that lease merely because one prompt is pending.

Stop first closes admission and invalidates/cancels all still-unanswered forms and covered approvals, including a cancellation-triggered next form, then clears the public queue and requests abort. Observe separate handler/agent/dialog obligations for five seconds. No evidence by the deadline means stop-unconfirmed/recovery-required; disable sending, profile/session/model transitions and answers, retain available draft and show terminal/manual-end guidance. No automatic task replay or kill. Detached extension work is not claimed settled; reliably incompatible operations are excluded or the extension is excluded when separation is unavailable. Explicit End owned runtime and controlled recovery follow the persistent exact-child contract in ADR 0002, not an arbitrary PID action. Pending startup, error, stream loss, host loss, observed child exit, never-spawned failure and successful receipt retirement remain distinct. Cleanup of the retained exact run remains available when workspace execution is ineligible (restricted, no-folder or multi-root); it never grants trust/resource consent or bypasses startup eligibility. See the WI-010 cleanup correction in ADR 0002.
