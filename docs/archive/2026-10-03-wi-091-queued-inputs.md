## Bounded scope — confirmed 2026-10-03

1. Both Steer and Follow up accept the existing whole-file/selection text attachments; no image inputs, editor-buffer saving, new persistence or attachment formats. Preserve existing source-change confirmations. Admit a host-owned immutable snapshot only after final revision/session/eligibility checks; reject the complete request before sending if its full encoded input or recovery retention exceeds the existing queue budget. Do not silently truncate or raise that budget.
2. Allow discovered skill commands and prompt templates with arguments through public pi expansion. Recognized non-queueable built-in/extension commands show a clear busy-state error and preserve the draft; do not execute, convert to plain chat or defer them implicitly. Unrecognized slash input is explicitly rejected rather than silently reinterpreted. Respect the resource loading choice; do not enable trusted extensions to provide missing commands.
3. Keep original draft text and attachment snapshots distinct from upstream expanded queue text. Queue display and recall distinguish steering/follow-up and do not imply acceptance equals execution. Restore original input and snapshots only through an explicit action into an empty draft; never overwrite newer edits, silently reread changed files or send automatically. Retention stays session-scoped and host-owned under bounded existing budgets; sensitive upstream expansion must not be projected raw to the Webview.
4. Stop retains clear-queue then abort semantics. Delivery-unknown remains visibly uncertain: no automatic retry, no claim of exactly-once delivery or safe resend. Verify expansion attribution through representative public-API runtime evidence before claiming recovery correctness; if the API cannot prove identity, preserve uncertainty instead of guessing based on matching strings.
