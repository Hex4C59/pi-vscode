## 诊断与所选环境

现有安装自报 VS Code 1.139.1、内置 js-debug 1.117.0。原生 F5 启动开发窗口但调试器 attach 失败。复现入口为 host/f5-probe.cjs；red-f5-debug-trace.json 与 inspector-probe.json 保留证据：自有 IPv4 inspector 返回 HTTP 200，而 IPv6 拒绝连接。修改 launch address 和隔离请求选项未修复。loopback 字节转发使一次真实原生 F5 交互通过，但重复矩阵在 attach 后终止；实验保留于 relay-experiment/，不作为可靠修复交付。

选择：官方固定 VS Code 1.105.1 ZIP、隔离 executable/profile/extensions/HOME、原生 F5 及未修改的内置调试器。不采用 CLI development host 替代、不注入 resume 命令、不改用户安装。下载源为 Microsoft update 服务；host-tool/hash.txt 记录 SHA-256 18FF74B3B4BDC6763E27BA296D359B3332F9A6C1F5CF67AAA9189ED12698B06D。普通传输 reset，随后用有界 range 下载重组 ZIP 并成功解压。所选环境解除调试器阻塞，不声称原安装调试器已修好。

## 发现的产品缺陷与最小修复

1.105.1 不支持的辅助侧栏贡献会回退到 Explorer。原生 F5 已激活扩展，但 Focus Chat 因 workbench.view.extension.pi-vscode 命令不存在而失败。修复查询公开命令清单，已注册则先展开该容器，再聚焦已注册 Pi 视图。发现失败及已有容器失败仍向上传播。不做错误文本匹配、整体 catch，不增加视图或绕过信任。现代宿主辅助侧栏默认不变。

必要兼容切片已记入双语 PRD 与 ACTIVE。回归先因多调用不存在的容器命令而失败；最小实现位于 src/extension/piChatViewProvider.ts 及同属层级的 focus-chat.spec.ts。这是已有宿主 UI 能力，不新增跨层接口、持久化、依赖或 ADR 选择。
