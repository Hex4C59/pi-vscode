## 何时加载与先检查什么

编辑应用 `.ts` / `.tsx`、Node 脚本、依赖或 TypeScript／构建／lint／测试配置时加载。先读受影响代码与测试、`package.json`、锁文件、`tsconfig`、lint 和打包配置。沿用仓库的包管理器、命令与模块约定，不借顺手清理迁移工具链。仅应用与本次改动有关的章节。

新增公共 API、跨层依赖或持久化时，同时使用产品架构治理清单。本指南补充仓库规则，不构成架构变更批准。

## 类型与运行时校验

- 保持严格检查。公共边界明确输入／输出类型，清晰的局部变量使用推断；有意义的状态用可辨识联合表达，避免无关联的标志位与可选字段组合。
- 外部 JSON、消息、配置与捕获的错误，在收窄前按 `unknown` 处理。类型断言、泛型和接口不校验运行时数据。在接收边界、产生副作用前校验必需字段、允许值和协议版本；按契约处理未知字段。
- 优先使用类型收窄，避免 `any`、非空断言或双重断言。库边界或已成立的不变量确需断言时，限制在局部并说明依据。不通过降低编译器／lint 设置隐藏错误；局部抑制须注明原因。
- 业务区分缺失、空值和失败时，类型与逻辑也要区分。封闭联合的各分支须完整处理，避免新增状态静默落入默认路径。

## 模块与依赖边界

- 一起检查 `package.json` 模块模式、编译器模块解析、打包输出和实际部署运行时。保留必要的导入扩展名与现有 ESM/CJS 约定；打包成功不证明运行时兼容。
- 纯类型依赖优先用 `import type`，Node 内置模块优先用 `node:`。除非产品架构明确允许，浏览器／UI 包不得导入 Node 专用模块或特权 SDK；共享类型不能顺带引入运行时代码。
- 共享契约放在文档规定的归属位置，不临时重复声明。没有具体消费者或边界需求时，不新增共享目录、汇总导出、包装层或接口。
- 添加依赖前检查现有能力、运行时支持、包体积影响和安装时行为。用仓库包管理器更新 manifest 与锁文件。信任边界或集成变化按要求记入架构／ADR；避免私有包内部入口和未声明的本地链接。

## 异步任务与资源归属

- 等待或返回 Promise。后台任务必须有明确所有者和拒绝处理；单写 `void` 不会处理拒绝。事件回调须将失败交给所属错误处理路径。
- 监听器、订阅、定时器、流和子进程必须有清理所有者。成功、失败、取消和 dispose 时均应释放，包括初始化只完成一部分的情况；使用 `finally` 或框架的释放机制。清理重复调用仍须安全。
- 可能挂起的操作使用现有超时／取消机制。超时或 `Promise.race` 不会停止底层任务：须取消任务或阻止迟到结果修改当前状态。工作区／会话／视图可能变化时，在 `await` 后复核身份或代次。
- 对可能无限增长的流限制缓冲区与待处理任务，遵守流背压，不将进程输出无限追加到内存。交互宿主路径避免昂贵的同步 I/O。

## 错误与副作用

- 沿用现有错误约定。内部保留有用的原因和上下文，区分取消与失败，按需求给调用方可恢复结果。不吞异常、伪造成功或盲目重试非幂等操作。
- 诊断不得泄露密钥或敏感载荷；记录或展示捕获输出前进行脱敏和长度限制。不向低信任 UI 暴露原始异常转储。
- 文件系统／进程副作用前校验输入与权限。使用结构化参数，不把不可信文本拼进 shell 命令。路径／URI 处理须符合支持的平台与产品信任模型。

## 验证与报告

行为变更、回归修复或测试变更前阅读[测试指南](testing.zh.md)；测试位置、命名、收集与证据层级由该指南拥有。下列通用验证原则仍适用。

- 运行仓库相关 lint、类型检查／构建和测试命令。转译／打包不等于类型检查，要检查脚本实际覆盖范围。复用组合命令，避免重复等价检查；缺失的检查如实报告，不编造脚本。
- 针对逻辑变化和回归添加或更新行为测试。按改动覆盖畸形输入、失败／取消、迟到完成和清理路径；不为镜像实现或纯文案修改添加测试。
- 必要时为时间、进程、文件系统或宿主 API 提供窄测试替换点。避免真实凭证、用户状态、付费调用及不可控网络依赖。使用临时 fixture 并清理。
- 区分单元测试、真实集成检查和人工宿主验收。Mock 不能证明宿主生命周期或部署兼容性。报告执行命令、结果、未验证路径与实质限制；检查通过本身不关闭产品 gate。

## 如何维护本指南

任务暴露重复出现的 TypeScript／Node 故障、已批准的工具链变化或可复用验证经验时，在交接中更新对应规则及译文。项目专属路径和命令放在产品章节，技术包保持通用。仅在任务授权模板变更时更新模板包。不追加逐任务日志，不重复架构规则，不为填充指南扩大实施范围。

## pi VS Code 项目应用

- 当前配置以 `tsconfig.json`、`eslint.config.mjs`、`esbuild.mjs` 和 `package.json` 为准。此版本 TypeScript 开启严格检查并使用 Node16 模块解析；esbuild 输出以 Node 22 为目标的 CommonJS 宿主包，`vscode` 为外部依赖。保留 TypeScript 中现有的 `.js` 相对导入。这些配置不能证明兼容所有支持的 VS Code 宿主；运行时特性变化须在实际宿主验证。
- `src/extension/` 拥有 VS Code 能力，`src/adapter/` 负责运行时集成，`src/webview/` 提供展示。改边界前读[主架构](../../architecture/vscode-extension-architecture.zh.md)与 [pi 集成](pi-integration.zh.md)。宿主侧 HTML 构建器不代表 Webview 中执行的脚本获得 Node 或 pi SDK 权限。
- Webview 入站校验留在宿主，变更同步[消息契约](../../reference/webview-messages.zh.md)。异步操作保留工作区代次校验。不将密钥放入 HTML 或消息，不新增通用命令桥，不通过类型断言扩大项目资源权限。
- 相关代码变更使用 `npm run compile`（esbuild 加 `tsc --noEmit`）、`npm run lint` 和 `npm test`。需要单独类型检查时可用 `npm run typecheck`；compile 已包含它。当前 lint 覆盖 `src`，不覆盖 `scripts`，变更的 Node 脚本须单独审阅并测试。文档变更运行 `npm run docs:verify`，协作流程要求时运行 `npm run docs:health`。
- 仅在相关集成范围内、遵守隔离规则运行运行时／项目信任 spike。宿主／UI 行为变化时，将所需 F5 验证与自动测试分开报告。不要直接编辑生成的 `dist/` 输出。
