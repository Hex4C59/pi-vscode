## 何时加载

提出模块拆分、公共 API、跨层依赖、共享类型、持久化、大规模重构或关闭 Gate，以及声称架构正确或可发布之前，阅读本指南。纯文案修改及不涉及边界的改动无需架构评审。

## 评审步骤

1. **确定范围。** 阅读 [ACTIVE](../../ACTIVE.md) 中的当前提案与批准、相关[需求](../product-requirements.zh.md)和[架构](../architecture/vscode-extension-architecture.zh.md)。完成条件是明确本次改变的边界、所有者及验收条件；缺少必要决定或契约时，在 Prepare 记录缺口。
2. **选择维度。** 检查下方每个维度是否适用，只汇报相关行；看似相关但排除的维度须解释 N/A。每行均须有 `pass`、`gap` 或 `N/A`、仓库证据位置，以及风险或下一项检查。计划文字只能证明设计提案，不能证明实现。
3. **处理缺口。** 核对[消息契约](../reference/webview-messages.zh.md)、相关代码／测试及 [Gate](../reference/architecture-gates.zh.md)。提案可供批准之前，每个缺口须有范围明确的解决方式、显式延期或阻断条件。重要选择按 [ADR 条件](../decisions/README.zh.md)处理。
4. **给出结论。** 说明现在实现、先 spike、先补文档或被 ADR／Gate 阻塞，标明决策类（`none`、`spike-only`、`adr-after-approval`）及下方证据支持的成熟度。实现仍须遵循[协作指南](agent-collaboration.zh.md)的批准与验证流程。

权威与冲突规则以 [AGENTS](../../AGENTS.zh.md) 为准。引用实际存在的文件；缺少可选的模块目录文档或共享类型目录，本身不构成创建它的要求。

## 结构维度

| 维度 | 完成条件与证据 |
|------|----------------|
| 1. 模块分解 | 每个改动模块有明确主责，相关逻辑集中，能够独立测试。说明职责重叠或牵动无关层的变更；引用架构所有者和受影响模块。 |
| 2. 公共接口 | 具名用例操作有可校验、可替代测试的明确输入／输出；调用方依赖能力，而非存储／框架内部。低信任 UI 不获得通用 host、文件系统、shell 或 SDK 桥；引用操作与接收端校验器。 |
| 3. 依赖 | import 和调用遵循已规定的分层方向、没有循环；框架 handler 位于边缘。共享类型留在已有职责归属处，不把高权限运行时代码带入 UI；引用 import 与分层模型。 |
| 4. 契约 | 声称实现符合契约前，文档至少为 Outline；数据、前置条件、错误、空态／非法状态、顺序、关联、完成、超时、取消及重试／幂等规则明确。Living 契约与所属类型和测试同步修改；仅有签名不能证明行为。 |
| 5. 所有权 | 每项受影响资源均有明确的创建、状态与清理所有者。Adapter 转换上游数据，host 策略拥有产品状态，UI 展示投影。说明生命周期交接，避免两个模块独立修改同一权威状态。 |

## 行为与运行时维度

| 维度 | 完成条件与证据 |
|------|----------------|
| 6. 需求与范围 | 行为与验收可追溯到已批准 WI 切片；Draft 候选和范围外想法单独标明。引用 PRD 编号、批准及开放 Gate。 |
| 7. 领域模型 | 工作区、视图、运行时与会话含义明确且不同，身份稳定、不变量已说明。引用所属类型及架构／契约定义。 |
| 8. 状态机 | 合法转移、拒绝的操作、终态及恢复动作明确。引用状态所有者、契约及转移测试。 |
| 9. 并发 | 明确哪些工作并行、哪些串行；取消、替换、重载后的迟到事件不能修改当前状态，后台工作有清理所有者。引用代次／关联保护及交错测试。 |
| 10. 错误与恢复 | 用户可修、宿主和上游错误有可观察结果及恢复路径。所属边界集中处理诊断；超时不静默重试结果未知的副作用。引用失败契约与测试。 |
| 11. 生命周期与清理 | 订阅、待决请求及子进程清理覆盖初始化失败、取消、替换、崩溃和释放。说明关闭顺序并验证实际退出；发出终止请求本身不足。引用所有者与生命周期证据。 |

## 质量与交付维度

| 维度 | 完成条件与证据 |
|------|----------------|
| 12. 安全与信任 | 边界遵循[产品 L0](../../AGENTS.zh.md)：密钥留在 host，输入经过校验，不可信输出安全呈现，如实说明用户权限。报告未覆盖路径；凭证即使临时也不得进入 Webview。 |
| 13. 数据与持久化 | 每项保存数据有唯一权威、写入者、生命周期及迁移方式。应用／丢弃流程保留工作区数据。按 L0 使用公开 pi 会话 API，重要存储改变遵循 ADR／Gate 规则。 |
| 14. 可观测与隐私 | 诊断有界且归边界所有。普通日志排除凭证、完整 prompt、token 及敏感认证路径；引用日志／投影路径。 |
| 15. 性能与背压 | 流、载荷和队列均有界，限制与截断可见。交互路径避免阻塞 I/O，保持输入区／布局稳定；引用上限、溢出行为和相关测量。 |
| 16. 测试策略 | 新公共操作和状态转移有行为测试，实际运行适用脚本。按[测试指南](agent/testing.zh.md)区分 mock、真实运行时探针、F5 及安装包证据。 |
| 17. 构建、发布与升级 | 从 [package.json](../../package.json) 及构建配置核对版本和入口。验证所需开发态与打包运行路径，不依赖未声明的相邻仓库；升级遵循 [pi 集成](agent/pi-integration.zh.md)。 |
| 18. 兼容与版本 | 破坏性消息／schema 变更须明确使用方、版本／重置或迁移行为，以及适用 ADR 决策。引用契约版本与宿主支持证据。 |
| 19. 体验与无障碍 | 可见变更须定义加载、空态、错误、流式和停止状态，展示项目身份及重要操作。在目标宿主验证相关键盘、焦点、主题和无障碍行为。 |

## 汇报与成熟度

使用下表记录选定维度；只有“通过”而没有证据不算完成。

| 维度 | 状态 | 磁盘证据 | 若继续做的缺口或风险 |
|------|------|----------|----------------------|
| 受影响维度 | pass / gap / N/A | 文件、章节、测试或 Gate 编号 | 缺少条件及其处理方式 |

说明本次评审范围有证据支持的层级，区分设计与运行证据：

| 层级 | 所需证据 |
|------|----------|
| Direction | 已提议／认同的边界和所有者；未必有实现 |
| Implementable | 契约和所有者足够明确，无须臆造行为即可实现 |
| Verifiable | Living 契约、测试与 CI 守住所声称的约束 |
| Evolvable | ADR 和 Gate 保留后续变更评审所需的理由与验证 |

例如，窄化的 `stopChat` 消息可以满足接口条件，但取消行为仍可能缺乏证据：报告须指出缺少的稳定结束或关闭验证。接口形状或一次单元测试成功都不足以证明完整 Stop 行为。

修改治理文档后，同步译文并运行 `npm run docs:verify`。任务结果保存在已有交接中，本清单仅保留可复用标准。
