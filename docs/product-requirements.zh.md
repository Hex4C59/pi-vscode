## 产品方向（已认可）

以 **pi 为运行时**，提供接近 Claude Code／Codex 的本地 IDE Agent 工作体验。优先对齐上下文接入、任务执行、过程控制、修改审查与会话连续性，而不是复刻厂商云服务。扩展展示并编排 pi 的公开能力，不重实现 Agent 循环、provider 或会话格式。

保留左侧 Explorer，聊天优先使用辅助侧栏。可选编辑区标签不代表改变默认布局。参考客户端用于借鉴可观察的工作流程，不追求像素一致或未经支持的安全承诺。

## 首个可用版本（边界已确认；具体切片仍为 Draft）

初始目标用户在本地 VS Code 文件夹中开发，已有可工作的 pi provider 凭证。用户可以辨认当前项目和模型、附加相关代码、提出聚焦的修改任务、观察及停止执行、审查修改，并在之后恢复已知会话。

D-04 已确认边界：单个本地工作区文件夹（Git 或非 Git），每个 VS Code 窗口仅一个活跃运行会话；文本与显式的工作区文本文件／选区上下文；已有 pi 凭证；修改后审查及恢复本扩展在当前项目使用过的已知会话。完整 provider 登录界面、多根工作区、远程环境及并行会话不是首版承诺。范围批准不等于 Build 授权或技术可行性验证；下方具体切片仍为 Draft。

## 候选需求与验收

各项完整需求仍为 Draft，部分切片已有单独批准和验收。新增 Build 前，按[协作指南](guides/agent-collaboration.zh.md)将选定切片关联到一个 WI，明确可观察的验收与相关决策并记录批准。

### REQ-001 — 项目与信任可见性

执行任务前显示当前工作区文件夹。无文件夹时说明如何打开，不启动项目任务。不支持的多根情况应明确解释，不静默选择一个文件夹。工作区变化时，不把旧任务静默转到新项目继续。

区分 VS Code 工作区信任、pi 项目资源信任和工具审批。按已确认 D-03：VS Code 工作区未信任时不启动 Agent；不静默信任 pi 项目资源。VS Code 已信任工作区但用户拒绝 pi 资源信任时，允许继续会话，并明确显示未加载 pi 项目级资源。这不禁止普通项目文件读取，也不意味着排除所有上下文文件和用户／全局资源；实现前须验证 pi 的具体加载边界。不得将资源信任描述为文件系统／网络隔离。

#### WI-006 已验收切片 — 工作区与资源选择

WI-006 已验收的 UI 显示无目录、多根、远程宿主、非 file、未信任及合格状态，提供原生目录／信任管理入口和编辑器标题／命令面板聚焦入口。宿主保存绑定工作区身份的内存资源选择，视图重建保留，资格／身份变化及宿主重载清除；不自动授予信任或从 Webview 接受任意路径。

WI-006 当时仅记录选择，不启动 pi；随后 WI-007 接入根据选择启动运行时。零启动仅是 WI-006 历史切片的验收边界，不是当前产品要求。原始范围与验收见 [WI-006／WI-007 历史](archive/2026-09-21-closed-wi-history.zh.md)，当前状态转移与原生动作完成条件见[消息契约](reference/webview-messages.zh.md)。完整 REQ-001 与相关 Gate 尚未接受。

### REQ-002 — 模型就绪

显示所选 provider／模型，并允许从已配置的可用模型中选择。首版复用已有 pi 认证。无可用模型、缺少凭证或认证失败时，说明问题及恢复路径，不将凭证暴露在 HTML、日志或 webview 消息中。不静默切换 provider。配置显示正常不代表下次请求一定成功。

#### WI-008／WI-009 已批准切片 — 模型与 thinking 选择

在 WI-004 聊天输入区，以**单个模型 · thinking 合并 chip** 打开**锚定 Popover**，内含 `get_available_models` 提供的可折叠模型列表与 `get_available_thinking_levels` 提供的离散滑块。WI-009 已批准的样式为粗滑块、固定 `#168BFF` 填充／滑块头、无黄色焦点轮廓，并保留蓝色键盘焦点光晕；其余界面使用主题 token。

维护者于 2026-09-21 批准**流式期间选择，仅下一轮生效**。选择要求 runtime 就绪、代次匹配，且工作区非 `busy`、非 `modelBusy`；仅 `chatBusy` 不禁用选择。空闲时立即应用；流式期间保持已应用 chip 不变，单独显示待应用意图（每个字段最后一次选择覆盖前次）。在 `agent_settled` 后先应用模型、刷新能力，再仅在支持时应用请求的 thinking 档位；应用期间禁止发送与再次选择。失败显示有界错误并回读实际状态，不虚报成功、不自动重试修改。不实现凭证 UI、启动默认持久化或原生 Quick Pick。精确生命周期／错误规则见 [Webview 契约](reference/webview-messages.zh.md)。

维护者已确认空闲选择、基础 UI，以及 2026-09-21 19:44 的延后选择主路径：当前回复不变，结束后应用，下一条使用新配置。WI-008／WI-009 仍待汇总与明确收尾；审批／Stop 交错、失败回读及重启清理等边界未获完整独立手测。当前交接见 [`ACTIVE.md`](../ACTIVE.md)。

### REQ-003 — 显式编辑器上下文

允许附加工作区文件或带路径和行号的代码选区，发送前可查看并移除上下文。建议行为：发送时捕获当前编辑器内容，包括未保存修改；文件不可用／已删除时明确说明，不静默替换为旧的磁盘内容。实际上下文范围必须可见，不自动附加无关的已打开文件。遵循 D-04 的工作区纯文本附件、未保存内容及选区变化边界；工作区外附件延期。实现该切片前须确定单附件及总附件大小上限。

### REQ-004 — 可观察的任务执行

发送文本任务并展示流式回答与工具活动。适用时区分运行、等待审批、重试、压缩、完成、停止和失败状态。展示工具名称、目标及结果，限制输出体积并保护密钥。请求被接受不等于任务完成；排队续跑或自动重试尚未结束时不得显示完成。

#### WI-004 已验收切片 — 文本流式

运行时就绪后接受有界纯文本，并增量显示助手文本。复用既有 pi 配置，模型／凭证／provider 失败须显示有界恢复信息且保护密钥。请求受理与任务完成分开显示；宿主清除失效运行时的内存对话并拒绝迟到事件。具体消息与完成边界见[消息契约](reference/webview-messages.zh.md)。

[WI-004 历史](archive/2026-09-21-closed-wi-history.zh.md#wi-004)保存最小切片的批准、验收与排除项；其原始 `--no-tools` 配置已由 WI-010 受控执行替代。模型选择、Stop 和工具审批分别来自后续获批切片，附件及会话历史仍未包含。原始版本调研见 [0.85.1 RPC 证据](discussions/2026-09-21-wi-004-rpc-evidence-0.85.1.zh.md)。

### REQ-005 — 停止与恢复

提供停止全部操作，清除排队续跑并请求取消活动任务。在运行时稳定结束或报告关闭失败前显示停止中。取消不会撤销已完成的副作用。运行时断开／崩溃后明确显示中断，保留未发送输入，不自动重复可能有副作用的任务。重启／重试须由用户明确操作。

### REQ-006 — 执行审批策略

建议首版提供两种策略：**操作前询问**和**自由执行**。前者按已确认规则允许、询问或拒绝覆盖范围内的工具调用；后者跳过逐工具弹窗，但保留项目信任和密钥保护。默认规则已在下方 D-01 确认；具体工具覆盖仍需验证，授权范围与有效期已在 D-02 确认。不承诺自动风险分类器或与 Codex 等价的沙箱。

对覆盖范围内需审批的调用，批准前不得执行。展示工具、目标／命令及有意义的输入。拒绝、关闭或超时不能当作批准。停止／断开须取消待决审批；迟到回复不能授权另一个调用。提供单次授权；范围能够可靠展示与匹配时，也提供 D-02 定义的当前运行会话授权。会话授权不等于自由执行。切换模式不得静默批准已等待的操作。

第三方扩展可能在普通工具调用之外执行代码。须说明其信任与覆盖范围，不得宣称审批 UI 约束全部扩展代码、shell 子进程或网络活动。接受本需求前必须通过审批覆盖范围的 spike。

#### WI-010 已批准切片 — 思考展示与受控执行（已关闭，2026-09-21）

此 REQ-004／REQ-005／REQ-006 切片批准实际工具执行，沿用 D-01／D-02。受控配置只加载自带审批扩展，禁用第三方扩展发现；项目资源同意不能重新启用它们，也不等于工具授权。完整自由执行仍延期，其他上下文和可信用户配置未因此全部排除。

仅展示上游实际提供的 thinking 文本／摘要。可折叠思考／工具卡使用稳定增量渲染，保留展开、焦点和滚动；最终消息校正正文，累计输出替换旧快照。工具开始表示准备中，不证明副作用已发生。审批展示完整有意义的输入；展示输出有界并明确提示截断，总量超限不跳过审批。Stop 保留未发送草稿。

当前批准的自动允许范围仅为工作区内 canonical 普通文件的 `read`。搜索／列目录、编辑／写入、shell 及外部路径需询问；未知工具拒绝。不存在或无法可靠解析的目标仅可单次授权。会话文件授权匹配工具类别和 canonical 路径；shell 授权匹配工具、canonical cwd 及完整输入／执行条件，不扩大成目录或命令前缀。授权可查看／撤销，其有效期按 D-02。

自带审批组件缺失或握手未验证时阻止启动，界面不得声称可用。过大、无法审核或含凭证类字段的审批输入直接拒绝。Stop 先取消待决审批、清除排队续跑，再请求中止；稳定结束或明确失败／关闭前保持停止中，不自动重放可能产生副作用的任务。规范化不能消除文件系统替换竞态，Stop 不回滚也不保证所有后代进程退出；这是执行策略，不是沙箱。输出过滤尽力而为；可信用户凭证命令在工具审批覆盖范围外。

[WI-010 收尾记录](archive/2026-09-21-closed-wi-history.zh.md#wi-010)保存四项 F5、自动化、离线及包验证证据。四项 F5 支持该限定切片关闭；完整授权／生命周期矩阵、已安装 VSIX 及边界 ADR 仍待完成，见 ACTIVE。职责见[架构 §7](architecture/vscode-extension-architecture.zh.md)，消息、上限、握手与取消顺序见[契约](reference/webview-messages.zh.md)。本切片不将整份 PRD 或 Gate 提升为 Accepted。

### REQ-007 — 修改后审查

提供受影响文件入口，能查看相关差异并导航到源码。明确修改已经应用，不将事后 diff 呈现为事前审批。保留用户已有修改，不将整个脏工作区都归因于 Agent。命令造成的修改无法可靠归因时，应披露限制，不宣称完整覆盖本任务独有变更。不包含通用撤销或自动 Git reset／stash。

### REQ-008 — 会话连续性

支持新建对话，及明确恢复本扩展此前使用过的已知会话，包括历史和项目身份。重载视图不得静默重复启动任务。会话缺失／不可用时提供可恢复错误。不静默将会话恢复到其他项目。通过 pi 会话 API 操作，不解析或重写会话文件。完整 pi 历史发现、并发会话和分支界面延期。

## 产品决定与待确认事项

- **D-01 — 初始审批规则（维护者已确认，2026-09-19）。** 默认操作前询问；覆盖范围内的工作区只读文件操作自动允许，edit／write、shell 执行及外部路径访问需询问。这是工具策略，不保证 shell 无法越界或联网。具体工具覆盖及失败行为需要验证。
- **D-02 — 授权范围与有效期（维护者已确认，2026-09-19）。** 提供**仅允许本次**和**本会话允许此范围**；首版不提供持久允许列表。授权范围与期限分开展示。这是参考竞品后确定的本产品规则，不宣称其各客户端行为完全一致。
  - 单次授权绑定当前待执行调用及其参数，不能用于另一次调用。
  - 会话文件授权绑定当前工作区／会话身份内明确的操作类别和文件路径，允许后续匹配的操作，而不只是原始 diff；不隐式授权整个目录或 shell。工作区外访问须单独展示目标及读／写类别，不继承工作区内授权。
  - 会话 shell 授权绑定工作目录、完整命令及相关执行条件，不自动扩大成命令前缀。命令匹配不证明其引用脚本或副作用没有变化。无法可靠表达和匹配范围时，仅提供单次授权。
  - 会话指当前工作区内正在运行的 Agent 会话实例，不是永久保存的聊天记录。隐藏／重开侧栏仅在后台会话仍存活时保留授权。一轮任务结束或停止本身不清除已授予的会话权限；停止仍取消待决审批。
  - 新建／切换会话、切换工作区或重启运行时清除授权。恢复历史会话需要重新授权，不从聊天记录恢复临时权限。用户可查看并撤销授权；撤销影响后续调用，不撤销已完成的副作用。
  - 验收须验证同范围复用、范围变化重新询问、上述生命周期事件的失效及迟到审批回复保护。具体匹配实现仍须审批 spike 验证。自由执行是独立模式，遵循下方已确认的 D-02 补充规则，不从会话授权推导。
  - **模式生命周期补充（维护者已确认，2026-09-19）：** 新建或重新建立运行会话时默认操作前询问。恢复历史会话、重启运行时、重载扩展宿主或切换工作区，不自动恢复自由执行。可以提示之前使用的模式，但启用须用户明确选择，并警告文件／命令将按当前用户环境权限直接执行，不代表隔离。
  - 同一后台会话仍存活时，隐藏／重开侧栏、普通回合结束及停止操作保留当前模式。始终明确显示自由执行状态，允许随时切回。
  - 切到自由执行不得自动批准已有待决请求。切回操作前询问对后续工具调用生效，不撤销副作用，也不停止已经运行的操作；取消操作使用停止功能。
  - 首版不提供永久默认自由执行配置，项目配置与聊天记录不得静默开启。验收须覆盖重置／保留边界、待决请求处理及可见的模式提示／警告。
- **D-03 — 拒绝资源信任（维护者已确认，2026-09-19）。** 在 VS Code 本身信任工作区时，允许明确标示的不加载 pi 项目级资源的会话；否则不启动。工具审批仍独立生效。须验证启动及会话切换时的资源加载边界；本产品决定不代表运行行为已验证。
- **D-04 — 版本边界（维护者已确认，2026-09-19）。** 交付涵盖显式上下文、模型选择、流式执行、审批／停止、修改后审查及已知会话恢复的本地工作流程，边界如下：
  - 单个本地工作区文件夹，可以有 Git，也可以没有。无文件夹及多根情况须明确解释，不静默选择项目。Remote SSH、Dev Containers 和 WSL 扩展宿主环境延期。项目边界不是文件系统隔离；外部路径工具访问仍遵循 D-01／D-02。
  - 复用已有 pi 凭证和模型配置，完整登录／配置 UI 延期。明确说明凭证缺失、模型不可用及认证失败，链接 pi 配置说明，提供外部配置后的显式刷新／重连恢复路径。不重实现凭证存储，不向 webview 暴露密钥。
  - 每个 VS Code 窗口仅一个活跃运行会话，不是只能保存一个对话。支持新建对话及选择本扩展在当前项目使用过的历史会话。切换前停止活动任务并等待稳定，不遗留隐形后台任务。恢复历史遵循 D-02 的权限／模式重置规则，不恢复历史代码状态。并行会话、分支 UI 和全局 pi 历史发现延期。
  - 修改后审查补充而非替代操作前审批。提供受影响文件入口、相关文本 diff 和源码跳转，明确修改已应用。不承诺逐 hunk 接受／拒绝流程、通用撤销、自动 Git reset／stash 或 checkpoint 回滚。
  - 仅显式附加工作区文本文件或选区，显示路径／行号，允许预览及移除。不自动附加无关的已打开文件。图片、PDF、目录递归附件及外部路径附件延期。未保存编辑器内容可作为上下文，但不得自动保存；说明其可能与运行时磁盘读取不同。可靠跟踪变化后的选区，否则要求重新附加，不静默复用旧行号。单附件及总附件均须有上限，超限明确拒绝并提示处理，不静默截断；具体数值在 REQ-003 Prepare、Build 前确定。
  - 区分工具记录可确认的目标文件与任务期间观察到的工作区变化。保留用户原有修改；Git 相对 HEAD 的差异是工作区差异，不自动视为本任务独有差异。能够可靠捕获时展示修改前后的文本差异，披露 shell／并发编辑的归因限制。不承诺完整的任务独有归因，但仅链接 Git 不满足审查要求。具体归因验收边界在 REQ-007 Prepare、Build 前确定。

## 技术证据与验证门槛

能力核对基于已安装 pi `0.85.1` 的公开 README 及文档（`rpc.md`、`sdk.md`、`extensions.md`、`skills.md`），不是对最新分支的推断。此前完成的是文档调研，不是端到端运行验证。

## 非目标与延期能力

- 复刻厂商云端执行、账号订阅和计费体系。
- 重实现 pi 的 Agent 循环、provider 栈、压缩或会话存储。
- 本提案不包含自动风险审批、沙箱保证、通用回滚或修改前逐行批准。
- 完整认证 UI、全局历史搜索、多会话并行、多根及远程环境支持不作为首版承诺。
- 原生计划模式、子 Agent、MCP 市场、丰富附件和检查点体验，须另行定范围并验证。
- 默认编辑区标签聊天，或仅以 VS Code 原生 Chat Participant 作为 UI；可选界面继续延期。

## 需求生命周期与批准

先起草行为再请求批准，缺少批准不是保留空 PRD 的理由。WI 进入 Build 前，记录是否用户可见、关联选定需求和可观察验收、解决相关待决项，并取得维护者确认。纯技术 WI 说明无需新增产品需求的原因。Close 时将实际行为与已批准切片对照，记录延期差异。

不得将这份含未决提案的文档整体提升。提升前须将未决／延期候选与明确批准的范围分开，并在双语文档中明确批准边界。然后才能经维护者授权将已同意范围标为 Accepted、更新 WI 追溯并运行 `npm run docs:verify`。关 gate 和用户验收仍是独立决定。需求被替代时，按[归档规则](archive/README.zh.md)保留原因及替代依据。
