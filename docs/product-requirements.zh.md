## 产品方向（已认可）

以 **pi 为运行时**，提供接近 Claude Code／Codex 的本地 IDE Agent 工作体验。优先对齐上下文接入、任务执行、过程控制、修改审查与会话连续性，而不是复刻厂商云服务。扩展展示并编排 pi 的公开能力，不重实现 Agent 循环、provider 或会话格式。

**已确认澄清（2026-09-22）：** 在不修改 pi agent 核心的前提下，基于标准发行版 pi 及有文档的公开 API 制作此 VS Code 插件。支持添加／加载自定义 **pi 扩展**，既可使用现有扩展，也可让 AI 编写；这不承诺承载任意 VS Code `.vsix` 扩展。上游增强是可选的未来改进，不是本项目或基线交付的前提；提出依赖上游前，应评估当前声明发行版上的可行限定方案。不内在要求每个外部扩展采用本插件专用协议，也不承诺每个扩展或原样自定义 TUI 都可用。

保留左侧 Explorer，聊天优先使用辅助侧栏。可选编辑区标签不代表改变默认布局。参考客户端用于借鉴可观察的工作流程，不追求像素一致或未经支持的安全承诺。

## 下一可用交付（2026-09-22 修订目标；Draft）

**平台变更（维护者确认，2026-09-30）：** 自用验收平台由本文原述的「Windows 本地 VS Code」改为 **macOS 本机 VS Code**；维护者只在 macOS 上测试，Windows 实机 F5 与安装版 VSIX **移出验收范围**，不再计为待补缺口。原 Windows 表述作为历史保留，不再代表当前验收平台。此变更不改变 Cursor、公开发布、全生态或其他 OS 的既有排除项，也不接受整份 Draft。

下一目标是**维护者自用、macOS 本机 VS Code 上的已安装 VSIX**，不是公开发布。Cursor 尽力兼容，单列证据，不继承 VS Code 验收。保留单个本地工作区文件夹（Git 或非 Git）、每窗口一个活跃运行会话、已有 pi 凭证，以及显式的工作区文本文件／选区上下文。完整 provider 登录界面、多根、远程环境及并行会话仍不在此目标内。

保留 pi 已配置模型、AGENTS.md／skills／提示词、扩展命令／自定义工具／钩子、标准扩展交互及终端已保存会话的价值。核心编程工作应能在插件内独立完成；终端专用能力可回终端，并明确限制。REQ-009 定义代表性兼容，而非任意生态对等。

验收闭环为：附加代码 → 请求修改 → 观察工具与审批 → 必要时 Stop → 查看实际差异 → 之后恢复对话。自用目标验收还要求重启／失败恢复及至少一个真实扩展，不能只有合成夹具或 F5。REQ-006 新增显式信任的扩展执行这一独立目标；跳过工具审批延期至此次自用目标之外，并非永久取消；REQ-008 将原本仅恢复本扩展已知会话的目标扩展为当前项目已保存会话。下方保留 D-01～D-04 历史；这些修订既不改变已交付／已批准切片，也不代表技术可行性已验证。

## 视觉重设计方向（2026-09-23）

维护者选择以所给 Codex 截图的简洁感为视觉参考、Roo Code 前端源码为实现参考，允许重新审视产品功能、包括增删；仅下方具体选择已经确认。既有需求保持有效，除非此处明确修订。这记录产品方向，不是实施授权或验收。

**范围与密度（Q1–Q4）：** 围绕现有 pi 工作流（会话、上下文、模型、执行、审批、修改审阅）重设计，不增加 Plan 模式或并行会话能力。优先适配 320–400px 侧栏，兼容 280px 和更宽视图。思考／工具活动默认显示简短进度，详情按需展开；待处理审批、错误和 Stop 状态保持明显。

**已确认布局与展示（Q5–Q9）：**

| 区域 | 已确认行为 |
|------|------------|
| 会话／空状态 | 按 2026-09-27 维护者视觉反馈修订 Q5：空白页不再展示最近会话，历史默认收起；顶部使用带可访问名称／提示的历史与新建图标。点击历史图标后展开当前项目历史，采用标题＋简短修改时间的紧凑行，摘要／完整时间按需查看；再次点击图标或返回关闭历史。输入区保持在底部。既有顺序交接确认与临时授权清空规则继续有效。 |
| 附件 | 输入区内的 `+` 菜单提供显式添加文件／选区。已选附件以紧凑标签展示，可预览／移除。无附件时隐藏容量数字；来源变化确认和超限错误仍明显。通过 `+` 菜单保留附件历史入口（Q12）。 |
| 待处理审批 | 审批卡放在输入区上方，可展开完整输入与范围。保留单次允许、符合条件时的本会话范围允许、拒绝。历史工具活动仍在对话中。多卡选择遵循 Q14；默认可见的必要信息遵循 Q15。 |
| 修改审阅 | 有审阅数据时在输入区上方显示紧凑入口，展开文件列表并打开原生 diff；无数据时不占位。计数和标签区分工具报告目标、实际观察变化及不可用快照，不暗示完整归因或回滚。 |
| 消息正文 | 增加基础 Markdown：标题、列表、链接、代码块与复制。附件快照和审批输入保持原文。Markdown 不执行 HTML。表格、语法高亮不在所选基础渲染范围内。 |

**已确认导航与空间处理（Q10–Q12）：** 完整会话列表替换中间消息区，同时保留当前草稿、执行状态、Stop 和新到审批。返回时恢复原阅读位置；打开列表不切换活跃会话。新建／恢复仍遵守既有确认与停止完成规则。短视口优先保证审批操作和 Stop，修改审阅收为一个入口，长审批详情局部滚动，输入区保持可操作。输入区的紧凑权限入口提供执行策略说明及当前会话授权查看／撤销；附件 `+` 菜单同时提供附件历史入口。隐藏正常状态下重复的 Ready／草稿已同步／空容量文字，在相关附件操作处提供快照限制说明，错误及必要确认直接显示。项目资源同意仍与工具审批区分。

**已确认活动与审批选择（Q13–Q14）：** 每条助手消息显示一行紧凑活动摘要；展开查看关联的思考／工具条目，再展开单项详情。摘要由既有状态派生，不额外调用模型，也不声称具备整轮用户任务关联。存在多项待审批时，初始展开最早请求，并显示待处理数量和可选择的简短列表。逐项作出决定，保持既有有效期和过期响应规则；选择／展开请求不延长有效期，也不授予权限。

**已确认审批信息（Q15）：** 工具名称、操作目标和授权范围默认可见；执行命令时完整命令直接展示，长内容局部滚动。大段文件内容等放入可展开详情。精简卡片不能隐藏决定所需的目标／范围，既有完整输入仍可查看。

**已确认视觉审阅顺序（Q16）：** 先在浏览器可交互预览中展示新会话、对话、执行、审批、附件变更和错误等代表状态，维护者确认视觉后再接入正式侧栏并执行真实宿主验证。预览使用明确标识的模拟宿主，不能当作真实执行／审批／持久化验证。已选择的窄栏和宽度兼容、短视口操作、主题与键盘可访问性均须进入后续验证方案。

**Q16 本次委托评估（2026-09-27 UTC）：** 代理按本次明确委托完成实际浏览器视觉／交互评估，修复失联后对话／草稿可读性及错误可见性后通过；允许正式接入，不冒称维护者亲验，不替代随后原生 F5／安装包验收。证据与范围见[评估](archive/2026-09-27-wi-019-formal-chat.zh.md)。

### REQ-006 — 执行审批策略

**WI-013已接受限定选择（2026-09-28 Asia/Shanghai；ADR0002）：** 扩展共享本地恢复存储域同时只准入一个Pi runtime；共享该域的第二窗口必须显示已占用／状态未知且不spawn，不是终端session锁或机器级锁。Stop未确认／host丢失后跨reload保留禁止，另提供显式“结束自有runtime”操作；必须积极观察owned child退出并由用户有意恢复受控执行。不为制造扩展兼容自动终止，不重放任务、不静默重启trusted。独立观察者无法提供证据则恢复不可用，不接受PID不存在或用户断言。确认前披露单runtime限制及observer丢失边界，本片不支持同域并发runtime。[ADR 0002](decisions/0002-interaction-contract-route.zh.md)记录备选、生命周期metadata边界和所需验证。

### REQ-008 — 会话连续性

支持新建对话，并列出当前项目已保存的 pi 会话供主动选择，包括上次在终端 pi 中使用的会话，而不仅是本扩展已知会话。恢复对话历史与项目身份，不恢复历史代码状态或临时授权。切换前停止当前任务并等待稳定结束，不遗留隐形任务。重载视图不得静默重复启动任务。会话缺失／不可用及恢复失败须有明确可恢复错误；不静默恢复到其他项目。

终端与插件采用顺序交接：恢复同一已保存会话前先退出原入口，并要求用户确认已经退出。明确披露确认不强制保证独占；不承诺同时驱动、运行中接管或所有权保证。恢复遵循默认受控与重新授权规则。使用 pi 公开会话 API，不解析／重写会话文件。跨项目全局历史发现、并发会话和分支界面仍延期。枚举与安全交接的可行性须独立集成评估。

历史扩展当前未加载时，展示可恢复的历史，在可识别时提示缺失能力，并允许使用当前能力继续。不自动加载／安装扩展，不将历史工具当作当前可用能力；缺失工具不得虚报成功。不承诺完整依赖检测；上游恢复失败则进入明确的未就绪／恢复流程。

没有专用渲染器时，对可获得的工具名称、状态、文本和支持的结构化数据采用有界、安全的通用展示，明确标注截断和不支持内容；不执行历史代码还原界面。展示限制不定义模型恢复的上下文，后者仍归 pi 公开会话 API 管理。

超长历史先展示最近一段，明确提示存在更早历史并允许向前分批加载；每批及渲染预算通过性能验证确定。有界或折叠的工具输出须说明省略，UI 历史窗口不定义模型上下文。公开会话 API 保留的历史附件原文应可查看并标为历史快照；信息不足则明确不可恢复，不能重读当前文件冒充原附件。不增加额外附件持久化保证。

- **D-02 — 授权范围与有效期（维护者已确认，2026-09-19）。** 提供**仅允许本次**和**本会话允许此范围**；首版不提供持久允许列表。授权范围与期限分开展示。这是参考竞品后确定的本产品规则，不宣称其各客户端行为完全一致。
  - 单次授权绑定当前待执行调用及其参数，不能用于另一次调用。
  - 会话文件授权绑定当前工作区／会话身份内明确的操作类别和文件路径，允许后续匹配的操作，而不只是原始 diff；不隐式授权整个目录或 shell。工作区外访问须单独展示目标及读／写类别，不继承工作区内授权。
  - 会话 shell 授权绑定工作目录、完整命令及相关执行条件，不自动扩大成命令前缀。命令匹配不证明其引用脚本或副作用没有变化。无法可靠表达和匹配范围时，仅提供单次授权。
  - 会话指当前工作区内正在运行的 Agent 会话实例，不是永久保存的聊天记录。隐藏／重开侧栏仅在后台会话仍存活时保留授权。一轮任务结束或停止本身不清除已授予的会话权限；停止仍取消待决审批。
  - 新建／切换会话、切换工作区或重启运行时清除授权。恢复历史会话需要重新授权，不从聊天记录恢复临时权限。用户可查看并撤销授权；撤销影响后续调用，不撤销已完成的副作用。
  - 验收须验证同范围复用、范围变化重新询问、上述生命周期事件的失效及迟到审批回复保护。具体匹配实现仍须审批 spike 验证。自由执行是独立模式，遵循下方已确认的 D-02 补充规则，不从会话授权推导。
  - **模式生命周期补充（维护者已确认，2026-09-19）：** 新建或重新建立运行会话时默认操作前询问。恢复历史会话、重启运行时、重载扩展宿主或切换工作区，不自动恢复自由执行。可以提示之前使用的模式，但启用须用户明确选择，并警告文件／命令将按当前用户环境权限直接执行，不代表隔离。
  - 同一后台会话仍存活时，隐藏／重开侧栏、普通回合结束及停止操作保留当前模式。始终明确显示自由执行状态，允许随时切回。
  - 切到自由执行不得自动批准已有待决请求。切回操作前询问对后续工具调用生效，不撤销副作用，也不停止已经运行的操作；取消操作使用停止功能。
  - 首版不提供永久默认自由执行配置，项目配置与聊天记录不得静默开启。验收须覆盖重置／保留边界、待决请求处理及可见的模式提示／警告。
- **D-03 — 拒绝资源信任（维护者已确认，2026-09-19）。** 在 VS Code 本身信任工作区时，允许明确标示的不加载 pi 项目级资源的会话；否则不启动。工具审批仍独立生效。须验证启动及会话切换时的资源加载边界；本产品决定不代表运行行为已验证。
- **D-04 — 版本边界（维护者已确认，2026-09-19）。** 交付涵盖显式上下文、模型选择、流式执行、审批／停止、修改后审查及已知会话恢复的本地工作流程，边界如下：
  - 单个本地工作区文件夹，可以有 Git，也可以没有。无文件夹及多根情况须明确解释，不静默选择项目。Remote SSH、Dev Containers 和 WSL 扩展宿主环境延期。项目边界不是文件系统隔离；外部路径工具访问仍遵循 D-01／D-02。
  - 复用已有 pi 凭证和模型配置，完整登录／配置 UI 延期。明确说明凭证缺失、模型不可用及认证失败，链接 pi 配置说明，提供外部配置后的显式刷新／重连恢复路径。不重实现凭证存储，不向 webview 暴露密钥。
  - 每个 VS Code 窗口仅一个活跃运行会话，不是只能保存一个对话。支持新建对话及选择本扩展在当前项目使用过的历史会话。切换前停止活动任务并等待稳定，不遗留隐形后台任务。恢复历史遵循 D-02 的权限／模式重置规则，不恢复历史代码状态。并行会话、分支 UI 和全局 pi 历史发现延期。
  - 修改后审查补充而非替代操作前审批。提供受影响文件入口、相关文本 diff 和源码跳转，明确修改已应用。不承诺逐 hunk 接受／拒绝流程、通用撤销、自动 Git reset／stash 或 checkpoint 回滚。
  - 仅显式附加工作区文本文件或选区，显示路径／行号，允许预览及移除。不自动附加无关的已打开文件。图片、PDF、目录递归附件及外部路径附件延期。未保存编辑器内容可作为上下文，但不得自动保存；说明其可能与运行时磁盘读取不同。可靠跟踪变化后的选区，否则要求重新附加，不静默复用旧行号。单附件及总附件均须有上限，超限明确拒绝并提示处理，不静默截断；具体数值在 REQ-003 Prepare、Build 前确定。
  - 区分工具记录可确认的目标文件与任务期间观察到的工作区变化。保留用户原有修改；Git 相对 HEAD 的差异是工作区差异，不自动视为本任务独有差异。能够可靠捕获时展示修改前后的文本差异，披露 shell／并发编辑的归因限制。不承诺完整的任务独有归因，但仅链接 Git 不满足审查要求。WI-016 已记录 Goal 授权的有界捕获／归因契约和所需证据，不承诺完整的任务独有归因。

## 技术证据与验证门槛

原始能力核对基于已安装 pi `0.85.1` 公开文档，保留为历史。[2026-09-22 兼容性研究归档](archive/2026-09-22-pi-compatibility.zh.md)记录修订选择及已安装 pi `0.86.1` 的只读核对；两次研究都不是已执行的兼容测试。研究指出 RPC 支持标准对话框／文本，但不传输任意 TUI；命令发现不等于完整资源清单；SDK 可枚举项目会话，但 RPC 没有同等枚举命令。这不证明运行中接管或会话独占所有权。

RPC 文档提供 prompt、流式／工具事件、清队列及中止、模型选择、压缩／统计、会话切换／历史和扩展 UI 对话框。公开 SDK 提供会话枚举和认证操作，但它们不等于内建 RPC 命令。编辑器附件与审查 UI 由宿主负责。权限弹窗、计划模式、MCP 和代码检查点需要扩展，不是内建同等功能。会话 fork 不等于代码回滚。

上文定义完整目标；不表示每项都仍待完成，也不表示所有需求均已接受。限定 WI 的评估、日期、宿主／版本范围与限制见追溯表及链接归档；委托记录表示代理受托评估，不是维护者亲自检查。三个架构 gate 已由 [ADR 0004](decisions/0004-trust-and-lifecycle.zh.md) 按其记录的范围／证据限制单独接受。本 Draft 本身不授权记录范围外的工作，也不改变 ADR／gate 状态；WI-010／Goal 限定收尾见[归档](archive/2026-09-28-wi-010-goal-closure.zh.md)。见[架构门槛](reference/architecture-gates.zh.md)。

## 非目标与延期能力

- 公开发布验收、任意 pi 生态兼容、终端专用 UI 对等、运行中终端接管或强制会话独占。REQ-009 的代表性兼容与 REQ-008 的当前项目已保存会话枚举属于修订目标，不是整体延期。
- 复刻厂商云端执行、账号订阅和计费体系。
- 重实现 pi 的 Agent 循环、provider 栈、压缩或会话存储。
- 本提案不包含自动风险审批、沙箱保证、通用回滚或修改前逐行批准。
- 完整认证 UI、全局历史搜索、多会话并行、多根及远程环境支持不作为首版承诺。
- 原生计划模式、子 Agent、MCP 市场、丰富附件和检查点体验，须另行定范围并验证。
- 默认编辑区标签聊天，或仅以 VS Code 原生 Chat Participant 作为 UI；可选界面继续延期。

## 需求生命周期与批准

先起草行为再请求批准，缺少批准不是保留空 PRD 的理由。WI 进入 Build 前，记录是否用户可见、关联选定需求和可观察验收、解决相关待决项，并取得维护者确认。纯技术 WI 说明无需新增产品需求的原因。Close 时将实际行为与已批准切片对照，记录延期差异。

不得将这份含未决提案的文档整体提升。提升前须将未决／延期候选与明确批准的范围分开，并在双语文档中明确批准边界。然后才能经维护者授权将已同意范围标为 Accepted、更新 WI 追溯并运行 `npm run docs:verify`。关 gate 和用户验收仍是独立决定。需求被替代时，按[归档规则](archive/README.zh.md)保留原因及替代依据。
