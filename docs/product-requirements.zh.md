## 产品方向（已认可）

以 **pi 为运行时**，提供接近 Claude Code／Codex 的本地 IDE Agent 工作体验。优先对齐上下文接入、任务执行、过程控制、修改审查与会话连续性，而不是复刻厂商云服务。扩展展示并编排 pi 的公开能力，不重实现 Agent 循环、provider 或会话格式。

**已确认澄清（2026-09-22）：** 在不修改 pi agent 核心的前提下，基于标准发行版 pi 及有文档的公开 API 制作此 VS Code 插件。支持添加／加载自定义 **pi 扩展**，既可使用现有扩展，也可让 AI 编写；这不承诺承载任意 VS Code `.vsix` 扩展。上游增强是可选的未来改进，不是本项目或基线交付的前提；提出依赖上游前，应评估当前声明发行版上的可行限定方案。不内在要求每个外部扩展采用本插件专用协议，也不承诺每个扩展或原样自定义 TUI 都可用。

保留左侧 Explorer，聊天优先使用辅助侧栏。可选编辑区标签不代表改变默认布局。参考客户端用于借鉴可观察的工作流程，不追求像素一致或未经支持的安全承诺。

## 下一可用交付（2026-09-22 修订目标；Draft）

下一目标是**维护者自用、Windows 本地 VS Code 上的已安装 VSIX**，不是公开发布。Cursor 尽力兼容，单列证据，不继承 VS Code 验收。保留单个本地工作区文件夹（Git 或非 Git）、每窗口一个活跃运行会话、已有 pi 凭证，以及显式的工作区文本文件／选区上下文。完整 provider 登录界面、多根、远程环境及并行会话仍不在此目标内。

保留 pi 已配置模型、AGENTS.md／skills／提示词、扩展命令／自定义工具／钩子、标准扩展交互及终端已保存会话的价值。核心编程工作应能在插件内独立完成；终端专用能力可回终端，并明确限制。REQ-009 定义代表性兼容，而非任意生态对等。

验收闭环为：附加代码 → 请求修改 → 观察工具与审批 → 必要时 Stop → 查看实际差异 → 之后恢复对话。自用目标验收还要求重启／失败恢复及至少一个真实扩展，不能只有合成夹具或 F5。REQ-006 新增显式信任的扩展执行这一独立目标；跳过工具审批延期至此次自用目标之外，并非永久取消；REQ-008 将原本仅恢复本扩展已知会话的目标扩展为当前项目已保存会话。下方保留 D-01～D-04 历史；这些修订既不改变已交付／已批准切片，也不代表技术可行性已验证。

**已确认布局与展示（Q5–Q9）：**

| 区域 | 已确认行为 |
|------|------------|

**已确认活动与审批选择（Q13–Q14）：** 每条助手消息显示一行紧凑活动摘要；展开查看关联的思考／工具条目，再展开单项详情。摘要由既有状态派生，不额外调用模型，也不声称具备整轮用户任务关联。存在多项待审批时，初始展开最早请求，并显示待处理数量和可选择的简短列表。逐项作出决定，保持既有有效期和过期响应规则；选择／展开请求不延长有效期，也不授予权限。

## 候选需求与验收

各项完整需求仍为 Draft，部分切片已有单独批准和验收。新增 Build 前，按[协作指南](guides/agent-collaboration.zh.md)将选定切片关联到一个 WI，明确可观察的验收与相关决策并记录批准。

### REQ-001 — 项目与信任可见性

执行任务前显示当前工作区文件夹。无文件夹时说明如何打开，不启动项目任务。不支持的多根情况应明确解释，不静默选择一个文件夹。工作区变化时，不把旧任务静默转到新项目继续。

区分 VS Code 工作区信任、pi 项目资源信任和工具审批。按已确认 D-03：VS Code 工作区未信任时不启动 Agent；不静默信任 pi 项目资源。VS Code 已信任工作区但用户拒绝 pi 资源信任时，允许继续会话，并明确显示未加载 pi 项目级资源。这不禁止普通项目文件读取，也不意味着排除所有上下文文件和用户／全局资源；实现前须验证 pi 的具体加载边界。不得将资源信任描述为文件系统／网络隔离。

#### WI-006 已验收切片 — 工作区与资源选择

WI-006 已验收的 UI 显示无目录、多根、远程宿主、非 file、未信任及合格状态，提供原生目录／信任管理入口和编辑器标题／命令面板聚焦入口。宿主保存绑定工作区身份的内存资源选择，视图重建保留，资格／身份变化及宿主重载清除；不自动授予信任或从 Webview 接受任意路径。

WI-006 当时仅记录选择，不启动 pi；随后 WI-007 接入根据选择启动运行时。零启动仅是 WI-006 历史切片的验收边界，不是当前产品要求。原始范围与验收见 [WI-006／WI-007 历史](archive/2026-09-21-closed-wi-history.zh.md)，当前状态转移与原生动作完成条件见[消息契约](reference/webview-messages.zh.md)。完整 REQ-001 与相关 Gate 尚未接受。

维护者已确认空闲选择、基础 UI，以及 2026-09-21 19:44 的延后选择主路径：当前回复不变，结束后应用，下一条使用新配置。WI-008／WI-009 仍待汇总与明确收尾；审批／Stop 交错、失败回读及重启清理等边界未获完整独立手测。当前交接见 [`ACTIVE.md`](../ACTIVE.md)。

### REQ-003 — 显式编辑器上下文

允许附加工作区文本文件或代码选区，预览确切上下文并在发送前移除。整文件附件在发送时读取最新编辑器内容。选区在附加时固定快照，显示来源路径与原始范围；来源文档变化后，须重新附加或明确确认发送旧快照。不得将旧行号呈现为当前位置。发送后的历史附件保留实际发送时的内容。

允许未保存的编辑器快照，并明确区别于磁盘内容；绝不自动保存。文件不可用／已删除时明确说明，不静默替换为旧的磁盘内容。不自动附加无关的已打开文件。图片、PDF、目录递归及外部路径附件仍延期。已确认候选上限为单项 256 KiB、每条消息附件合计 1 MiB、最多 20 项，按实际附件文本的 UTF-8 字节数计量，用户正文保持独立限制。添加时检查，发送时按最终内容复查；任何超限阻止整条发送并提示缩小或移除，不静默截断或漏发。这些产品上限仍须验证传输／渲染能力，不保证模型上下文足够。

默认显示紧凑附件条目，包含相对路径、整文件／选区类型、选区原始范围、大小及未保存／旧快照状态，允许移除和按需完整文本预览，不强制逐项打开预览。整文件在附加后变化时暂停发送、更新状态，要求明确确认使用最新内容；再次变化则重新校验。确认不要求阅读完整预览。选区快照仍沿用上文明确选择旧快照的规则。

#### WI-014 分期验收候选 — T014-01

### REQ-006 — 执行审批策略

**两个独立策略维度（2026-09-22 确认）：** 扩展加载策略决定仅内置或显式信任第三方加载；工具审批策略决定询问或跳过覆盖范围内的审批提示。此次目标保留询问，包括允许一次与精确范围的活跃会话授权；跳过审批延期，并非永久取消。加载可信扩展仍保留可覆盖工具调用的审批，不自动批准待处理调用；扩展内部执行可能绕过覆盖，须持续明确披露。两个概念不要求两个 UI 开关。下文配置中的受控表示仅内置加询问，可信表示显式信任加载加询问；两者均不是沙箱。

修订目标区分**受控执行**（默认）与**显式信任的扩展执行**。新建或重启运行时默认受控，不执行第三方扩展；加载可信扩展须明确确认，并显示覆盖范围警告。项目资源同意不等于扩展执行同意。可信扩展执行不等于历史提案中的跳过全部逐工具审批：它承认覆盖范围内工具调用之外仍有可执行扩展代码，不代表通用授权或沙箱保证。受控工具策略及授权范围保留已批准的 D-01／D-02 与 WI-010 边界。

执行配置仅在空闲时切换。运行中须先显式 Stop 并等待稳定结束；不重放任务或撤销已完成修改。切换保留已保存对话和未发送草稿，清除临时工具授权，不承诺保留扩展内部临时状态。是否需要重建运行时仍是待验证的技术问题。切换失败进入未就绪状态，保留对话／草稿并禁止发送；恢复须由用户重试或重新启动受控配置。不静默回退、不重放任务，也不宣称已回滚扩展初始化的副作用。此执行配置规则不改变 WI-008／WI-009 的下一轮模型／thinking 选择。

对覆盖范围内需审批的调用，批准前不得执行。展示工具、目标／命令及有意义的输入。拒绝、关闭或超时不能当作批准。停止／断开须取消待决审批；迟到回复不能授权另一个调用。提供单次授权；范围能够可靠展示与匹配时，也提供 D-02 定义的当前运行会话授权。会话授权不等于自由执行。切换模式不得静默批准已等待的操作。

第三方扩展可能在普通工具调用之外执行代码。须说明其信任与覆盖范围，不得宣称审批 UI 约束全部扩展代码、shell 子进程或网络活动。接受本需求前必须通过审批覆盖范围的 spike。

### REQ-007 — 修改后审查

提供受影响文件入口、相关文本差异及源码跳转。明确修改已经应用；事后 diff 不是事前审批。区分工具明确报告的目标与任务期间观察到的工作区变化。能可靠捕获时展示操作前后差异；Git 相对 HEAD 的差异是工作区差异，不自动视为任务独有差异。Shell 活动与并发编辑可能使观察结果混入其他修改：须披露限制，不承诺完整任务归因。仅提供 Git 跳转不满足审查要求。不提供逐块接受／拒绝、一键回滚、通用撤销或自动 Git reset／stash。

保留用户已有修改。对于插件可识别且能控制的写入，目标文档存在未保存编辑器修改时须阻止，要求用户先处理；不得为继续写入而自动保存。这一修订目标并非 WI-010 所交付。WI-016 已实现限定的内置 write/edit 保护；可执行证据和待接受项由 ACTIVE 管理。shell／可信扩展绕过及最终执行前检查之后的编辑，使完整脏缓冲区保护无法保证。

审阅快照仅保证在当前活跃运行会话内保留，包括隐藏／重建侧栏；运行时重启或切换会话后明确提示旧差异可能不可用，不承诺跨会话快照持久化。文件后来变化时仍保留操作当时的前后差异，标为历史快照，可检测时提示当前文件已变化。源码跳转不保证旧行号准确；不静默替换成当前 Git 差异，也不从这些快照覆盖当前文件。

### REQ-008 — 会话连续性

支持新建对话，并列出当前项目已保存的 pi 会话供主动选择，包括上次在终端 pi 中使用的会话，而不仅是本扩展已知会话。恢复对话历史与项目身份，不恢复历史代码状态或临时授权。切换前停止当前任务并等待稳定结束，不遗留隐形任务。重载视图不得静默重复启动任务。会话缺失／不可用及恢复失败须有明确可恢复错误；不静默恢复到其他项目。

终端与插件采用顺序交接：恢复同一已保存会话前先退出原入口，并要求用户确认已经退出。明确披露确认不强制保证独占；不承诺同时驱动、运行中接管或所有权保证。恢复遵循默认受控与重新授权规则。使用 pi 公开会话 API，不解析／重写会话文件。跨项目全局历史发现、并发会话和分支界面仍延期。枚举与安全交接的可行性须独立集成评估。

历史扩展当前未加载时，展示可恢复的历史，在可识别时提示缺失能力，并允许使用当前能力继续。不自动加载／安装扩展，不将历史工具当作当前可用能力；缺失工具不得虚报成功。不承诺完整依赖检测；上游恢复失败则进入明确的未就绪／恢复流程。

没有专用渲染器时，对可获得的工具名称、状态、文本和支持的结构化数据采用有界、安全的通用展示，明确标注截断和不支持内容；不执行历史代码还原界面。展示限制不定义模型恢复的上下文，后者仍归 pi 公开会话 API 管理。

超长历史先展示最近一段，明确提示存在更早历史并允许向前分批加载；每批及渲染预算通过性能验证确定。有界或折叠的工具输出须说明省略，UI 历史窗口不定义模型上下文。公开会话 API 保留的历史附件原文应可查看并标为历史快照；信息不足则明确不可恢复，不能重读当前文件冒充原附件。不增加额外附件持久化保证。

### REQ-009 — 代表性 pi 兼容

**自定义扩展加载目标（2026-09-22 确认）：** 允许用户通过受支持的 pi 公开加载 API，显式选择并加载现有或 AI 编写的 pi 扩展，遵循 REQ-006 的默认受控、明确执行同意及受覆盖工具审批。AI 编写不自动带来信任或兼容性，适用相同审阅、警告、失败处理和支持范围检查。AI 编写可以在本插件外完成；不隐含内置生成器／编辑器、市场／安装 UI 或包管理交付。用户如何指定／选择加载目标及如何校验目标仍属 Prepare 待定，不是获批 UI 或自动发现／执行。后续验收须覆盖两种来源的同意／拒绝、加载失败和受支持行为；此处不宣称已有新增验收。

本地答案失效、本地传输进度与观察到自有 child 退出，都是各自事实的有效证据，但不能冒充远端答案消费或通用扩展完成。精确远端关闭时刻、逐答案 ACK 和全局认证操作来源不是通用产品要求。缺失证据阻塞对应声明或依赖该证据的操作，不让整个项目等待新上游协议；保留下方 Stop 与恢复规则。

普通扩展对话框的取消只结束当前交互，返回协议的取消结果，不替换为默认选项或批准。扩展可以按自身逻辑继续，Stop 是独立操作；被拒绝的受覆盖工具调用不得执行。Stop 使待处理交互失效，迟到答案不得完成失效请求或授权替代请求。这不保证覆盖协议之外的扩展代码终止；无法满足的生命周期要求须记为兼容缺口。

**不满足 Stop 的交互（2026-09-22 讨论确认）：** 已知扩展命令／交互无法满足 Stop 契约时，将该操作标为不支持并引导终端使用。能可靠区分时保留独立验证过的其他能力，否则将整个扩展排除在支持的兼容范围外。不为兼容新增自动终止／重启运行时的补救方案；这不取消既有运行时故障／关闭处理，也不保证自动识别全部不兼容扩展。若交互已经待决才发现问题，使宿主侧答案失效，明确显示“未确认停止／不可继续”，阻止新任务，提示用户手动结束运行时后主动恢复。不宣称上游扩展已经停止或副作用已撤销；此失败状态行为仍是待验证目标，不是现有产品验收。

**标准交互呈现（WI-013 讨论）：** select／confirm／input／editor 优先统一在 Pi 侧栏呈现，保留操作上下文及 Stop／失败状态可见性。上游未指定回答期限时，不添加统一用户回答倒计时；明确的上游期限须遵守。传输失败与 Stop 稳定结束的期限不同于用户阅读／回答时间。一次呈现一个交互，使用有界待决队列并显示待处理数量，排队不得延长上游期限。队列溢出时保留已接收请求，经支持的协议响应取消／拒绝额外请求并告警；取消可能使扩展代码继续。请求持续涌入则进入明确交互故障状态、阻止新任务，不自动重启或宣称执行停止。确切容量、持续溢出阈值及载荷预算仍待确定，须于 Build 前明确；不得默认批准或静默替换旧请求。

通过约定的代表性成功与失败夹具保留五类能力，并披露不支持部分：

1. **Provider／模型配置：** 复用已有配置并验证选择；配置缺失／不可用或切换失败不得静默替换模型／provider。
2. **资源：** 验证 AGENTS.md、skills、提示词生效及项目资源允许／拒绝行为；说明排除的资源，不将资源同意混同为执行权限。
3. **扩展命令、自定义工具与钩子：** 验证合成样例及失败路径；证明受控配置禁止第三方扩展执行，而可信加载须明确同意并警告覆盖限制。
4. **标准扩展 UI：** 支持标准对话框与文本展示，覆盖取消、超时、Stop 和断连失败路径。终端专用／自定义 TUI 回终端并明确限制；不承诺任意终端 UI 对等或自动识别所有不兼容扩展。
5. **已保存会话：** 验证同项目终端／插件顺序交接、对话恢复、授权重置、会话缺失及 REQ-008／REQ-006 规定的切换失败与恢复。

自用已安装 VSIX 目标验收前，须在 Windows 本地 VS Code 验证这些夹具、核心编程闭环与重启／失败恢复，并在合成夹具之外验证至少一个真实扩展。Cursor 证据单列。精确夹具输入、预期结果与真实扩展仍待选择；维护者尚未指定固定扩展。通过这些检查不代表公开发布或广泛生态兼容。API 缺口须报告阻塞或重新协商范围，不能以成功演示掩盖。

### 历史基线 — D-01～D-04（2026-09-19）

下方保留历史批准背景，不追溯改写。对于未来提案，2026-09-22 的 REQ-003／REQ-006～REQ-009 目标在有差异处修订仅恢复本扩展已知会话和选区变化处理。仅空闲时切换执行配置不同于历史工具审批模式切换；维护者已将跳过工具审批延期至此次目标之外，未来跳过审批的生命周期规则须单独确认范围。既有 WI 批准与验收仍限于原切片；这些历史文字不授权新行为。

- **D-01 — 初始审批规则（维护者已确认，2026-09-19）。** 默认操作前询问；覆盖范围内的工作区只读文件操作自动允许，edit／write、shell 执行及外部路径访问需询问。这是工具策略，不保证 shell 无法越界或联网。具体工具覆盖及失败行为需要验证。
- **D-02 — 授权范围与有效期（维护者已确认，2026-09-19）。** 提供**仅允许本次**和**本会话允许此范围**；首版不提供持久允许列表。授权范围与期限分开展示。这是参考竞品后确定的本产品规则，不宣称其各客户端行为完全一致。
  - 单次授权绑定当前待执行调用及其参数，不能用于另一次调用。
  - 会话文件授权绑定当前工作区／会话身份内明确的操作类别和文件路径，允许后续匹配的操作，而不只是原始 diff；不隐式授权整个目录或 shell。工作区外访问须单独展示目标及读／写类别，不继承工作区内授权。
  - 会话 shell 授权绑定工作目录、完整命令及相关执行条件，不自动扩大成命令前缀。命令匹配不证明其引用脚本或副作用没有变化。无法可靠表达和匹配范围时，仅提供单次授权。
  - 会话指当前工作区内正在运行的 Agent 会话实例，不是永久保存的聊天记录。隐藏／重开侧栏仅在后台会话仍存活时保留授权。一轮任务结束或停止本身不清除已授予的会话权限；停止仍取消待决审批。
  - 新建／切换会话、切换工作区或重启运行时清除授权。恢复历史会话需要重新授权，不从聊天记录恢复临时权限。用户可查看并撤销授权；撤销影响后续调用，不撤销已完成的副作用。
  - 验收须验证同范围复用、范围变化重新询问、上述生命周期事件的失效及迟到审批回复保护。具体匹配实现仍须审批 spike 验证。自由执行是独立模式，遵循下方已确认的 D-02 补充规则，不从会话授权推导。
  - **模式生命周期补充（维护者已确认，2026-09-19）：** 新建或重新建立运行会话时默认操作前询问。恢复历史会话、重启运行时、重载扩展宿主或切换工作区，不自动恢复自由执行。可以提示之前使用的模式，但启用须用户明确选择，并警告文件／命令将按当前用户环境权限直接执行，不代表隔离。
  - 同一后台会话仍存活时，隐藏／重开侧栏、普通回合结束及停止操作保留当前模式。始终明确显示自由执行状态，允许随时切回。
  - 切到自由执行不得自动批准已有待决请求。切回操作前询问对后续工具调用生效，不撤销副作用，也不停止已经运行的操作；取消操作使用停止功能。
  - 首版不提供永久默认自由执行配置，项目配置与聊天记录不得静默开启。验收须覆盖重置／保留边界、待决请求处理及可见的模式提示／警告。
- **D-03 — 拒绝资源信任（维护者已确认，2026-09-19）。** 在 VS Code 本身信任工作区时，允许明确标示的不加载 pi 项目级资源的会话；否则不启动。工具审批仍独立生效。须验证启动及会话切换时的资源加载边界；本产品决定不代表运行行为已验证。
- **D-04 — 版本边界（维护者已确认，2026-09-19）。** 交付涵盖显式上下文、模型选择、流式执行、审批／停止、修改后审查及已知会话恢复的本地工作流程，边界如下：
  - 单个本地工作区文件夹，可以有 Git，也可以没有。无文件夹及多根情况须明确解释，不静默选择项目。Remote SSH、Dev Containers 和 WSL 扩展宿主环境延期。项目边界不是文件系统隔离；外部路径工具访问仍遵循 D-01／D-02。
  - 复用已有 pi 凭证和模型配置，完整登录／配置 UI 延期。明确说明凭证缺失、模型不可用及认证失败，链接 pi 配置说明，提供外部配置后的显式刷新／重连恢复路径。不重实现凭证存储，不向 webview 暴露密钥。
  - 每个 VS Code 窗口仅一个活跃运行会话，不是只能保存一个对话。支持新建对话及选择本扩展在当前项目使用过的历史会话。切换前停止活动任务并等待稳定，不遗留隐形后台任务。恢复历史遵循 D-02 的权限／模式重置规则，不恢复历史代码状态。并行会话、分支 UI 和全局 pi 历史发现延期。
  - 修改后审查补充而非替代操作前审批。提供受影响文件入口、相关文本 diff 和源码跳转，明确修改已应用。不承诺逐 hunk 接受／拒绝流程、通用撤销、自动 Git reset／stash 或 checkpoint 回滚。
  - 仅显式附加工作区文本文件或选区，显示路径／行号，允许预览及移除。不自动附加无关的已打开文件。图片、PDF、目录递归附件及外部路径附件延期。未保存编辑器内容可作为上下文，但不得自动保存；说明其可能与运行时磁盘读取不同。可靠跟踪变化后的选区，否则要求重新附加，不静默复用旧行号。单附件及总附件均须有上限，超限明确拒绝并提示处理，不静默截断；具体数值在 REQ-003 Prepare、Build 前确定。
  - 区分工具记录可确认的目标文件与任务期间观察到的工作区变化。保留用户原有修改；Git 相对 HEAD 的差异是工作区差异，不自动视为本任务独有差异。能够可靠捕获时展示修改前后的文本差异，披露 shell／并发编辑的归因限制。不承诺完整的任务独有归因，但仅链接 Git 不满足审查要求。WI-016 已记录 Goal 授权的有界捕获／归因契约和所需证据，不承诺完整的任务独有归因。

## 技术证据与验证门槛

原始能力核对基于已安装 pi `0.85.1` 公开文档，保留为历史。[2026-09-22 兼容性研究](discussions/2026-09-22-pi-compatibility.zh.md)记录修订选择及已安装 pi `0.86.1` 的只读核对；两次研究都不是已执行的兼容测试。研究指出 RPC 支持标准对话框／文本，但不传输任意 TUI；命令发现不等于完整资源清单；SDK 可枚举项目会话，但 RPC 没有同等枚举命令。这不证明运行中接管或会话独占所有权。

RPC 文档提供 prompt、流式／工具事件、清队列及中止、模型选择、压缩／统计、会话切换／历史和扩展 UI 对话框。公开 SDK 提供会话枚举和认证操作，但它们不等于内建 RPC 命令。编辑器附件与审查 UI 由宿主负责。权限弹窗、计划模式、MCP 和代码检查点需要扩展，不是内建同等功能。会话 fork 不等于代码回滚。

接受相关切片前须验证启动／会话切换的项目信任、覆盖范围内拦截的拒绝／取消／迟到回复、停止全部、安全恢复已保存会话、脏编辑器写入保护及差异归因，以及 REQ-009 的兼容／失败矩阵。待完成的 Prepare 工作包括已确认附件预算的验证、具体夹具和真实扩展选择、UI 降级呈现，以及会话枚举、配置切换／重建、资源加载和写入拦截的技术集成评估。使用单独批准的 spike 和公开 API；API 缺口可能阻塞或需重新协商。SDK 辅助或捆绑 pi 扩展须明确评估边界。本 PRD 不选择新架构、不接受 ADR、不关闭 gate，也不授权探针或 Build。见[架构门槛](reference/architecture-gates.zh.md)。

## 非目标与延期能力

- 公开发布验收、任意 pi 生态兼容、终端专用 UI 对等、运行中终端接管或强制会话独占。REQ-009 的代表性兼容与 REQ-008 的当前项目已保存会话枚举属于修订目标，不是整体延期。
- 复刻厂商云端执行、账号订阅和计费体系。
- 重实现 pi 的 Agent 循环、provider 栈、压缩或会话存储。
- 本提案不包含自动风险审批、沙箱保证、通用回滚或修改前逐行批准。
- 完整认证 UI、全局历史搜索、多会话并行、多根及远程环境支持不作为首版承诺。
- 原生计划模式、子 Agent、MCP 市场、丰富附件和检查点体验，须另行定范围并验证。
- 默认编辑区标签聊天，或仅以 VS Code 原生 Chat Participant 作为 UI；可选界面继续延期。

## 需求生命周期与批准

先起草行为再请求批准，缺少批准不是保留空 PRD 的理由。WI 进入 Build 前，记录是否用户可见、关联选定需求和可观察验收、解决相关待决项，并取得维护者确认。纯技术 WI 说明无需新增产品需求的原因。Close 时将实际行为与已批准切片对照，记录延期差异。

不得将这份含未决提案的文档整体提升。提升前须将未决／延期候选与明确批准的范围分开，并在双语文档中明确批准边界。然后才能经维护者授权将已同意范围标为 Accepted、更新 WI 追溯并运行 `npm run docs:verify`。关 gate 和用户验收仍是独立决定。需求被替代时，按[归档规则](archive/README.zh.md)保留原因及替代依据。
